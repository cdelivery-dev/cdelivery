登录后，先从当前任务选择入口。不同角色可见的编辑按钮不同；看不到某个管理入口时，先核对[角色与权限](/docs/zh-cn/administration/accounts/roles/)。

## 主要入口

| 入口 | 用于什么 |
| --- | --- |
| 概览 | 查看平台和应用的整体运行情况 |
| 分组及其应用列表 | 找到业务应用、创建应用、查看分组信息 |
| Insight | 配置观测服务、存储和数据采集 |
| Pingress | 配置 HTTP/HTTPS 入口及管理证书 |
| 数据卷服务 | 管理提供数据卷操作能力的平台组件 |
| 服务器 | 查看机器状态、标签、指标及该服务器的数据卷 |
| Agent | 配置 AI 模型和自动值班 |
| MCP / API 密钥 | 管理自己的接入凭据 |
| 设置 | 管理平台、用户和消息渠道 |
| 个人账户 | 修改个人资料、通知绑定、密码和两步验证 |

数据卷服务入口与服务器上的数据卷列表不是同一层次：前者管理组件，后者管理某台机器的实际卷。使用数据卷前按[数据卷管理](/docs/zh-cn/administration/nodes/volumes/)确认组件和目标服务器。

## 应用页面

打开应用后，围绕以下内容操作：

- **概览**：查看期望副本、实际运行情况及应用信息。
- **配置**：编辑镜像、运行参数、资源、网络、文件和存储等设置。
- **XHealth**：配置周期性业务检查，查看检查结果。
- **XJob**：管理计划任务并查看最近执行状态。
- **指标**：查看选定时间范围内的应用资源和请求指标。
- **日志**：查看应用输出，按支持的条件筛选。
- **事件**：查看平台记录的操作和运行变化。

编辑配置后，保存成功只表示操作已接受或配置已更新。涉及容器更新时，继续查看副本状态、日志及检查结果。

## 三种容易混淆的状态

| 状态 | 能说明什么 |
| --- | --- |
| 副本运行 | 容器进程已经运行 |
| XHealth 通过 | 最近一次配置的检查成功 |
| 客户端访问成功 | 当前客户端到业务入口的链路可用 |

其中一项正常，不能自动推出另外两项正常。排障时先确定失败发生在哪条链路。

## 按任务继续阅读

1. 部署和配置业务：进入[应用管理](/docs/zh-cn/guides/apps/)。
2. 查看日志和指标：进入[日志与指标](/docs/zh-cn/guides/observability/)。
3. 添加机器或分配账户：进入[平台管理](/docs/zh-cn/administration/)。
4. 接收通知或与助手对话：先配置[消息与通知](/docs/zh-cn/guides/automation/im/)。

语言和其他个人偏好在自己的账户中管理；AI 生成值班通知使用值班配置中的通知语言。
