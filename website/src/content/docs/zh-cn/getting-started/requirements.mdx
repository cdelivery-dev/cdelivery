安装前先确定服务器用途和控制台访问方式。单台机器即可开始；多台机器需要能够通过稳定地址相互通信。

## 服务器通信地址

服务器间使用的地址必须能被其他服务器访问。云服务器通常选择内网地址；浏览器访问控制台的地址可以不同，例如公网地址或 SSH 隧道的本地地址。

`127.0.0.1` 只适合本机访问场景。准备加入更多服务器时，不能把回环地址作为它们访问当前服务器的地址。安装器的 `--advertise-addr` 用于明确指定通信地址，重跑已有安装不会自动迁移该地址。

## 网络与访问

| 端口 | 用途 | 放行范围 |
| --- | --- | --- |
| TCP 9000 | 控制台及 API | 你的管理网络或 SSH 隧道 |
| TCP 80、443 | Pingress 的 HTTP/HTTPS 入口 | 需要访问应用的客户端 |
| 应用发布端口 | 直接访问应用，例如 TCP 8080 | 业务需要的客户端 |
| TCP 2377 | 服务器管理通信 | 参与部署的服务器之间 |
| TCP/UDP 7946 | 服务器发现与通信 | 参与部署的服务器之间 |
| UDP 4789 | 应用跨服务器通信 | 参与部署的服务器之间 |

同时检查云安全组和宿主机防火墙。服务器间端口不应对整个互联网开放。端口用途可参考 [Docker 网络要求](https://docs.docker.com/engine/network/drivers/overlay/#requirements)。

本地管理远程服务器时，可以使用：

```sh
ssh -L 9000:127.0.0.1:9000 your-user@server.example.com
```

保持 SSH 会话打开，然后访问 `http://localhost:9000`。首次应用教程使用的 8080 端口需要另行转发。

## 数据规划

数据库等有状态应用使用指定服务器上的本地数据卷。先选择存储服务器和备份方式，再创建应用。平台中的副本、回滚和重新部署不等同于数据库备份。

域名不是完成首次部署的前提。之后配置 HTTPS 时，准备域名管理权限，并让 DNS 指向运行 Pingress 的可达地址。

如果需要 IPv6，先检查宿主机地址、路由和防火墙，再阅读[网络常见问题](/docs/zh-cn/guides/networking/faq/)。安装器的网络准备不能替代外部连通性验证。

完成这些检查后，继续[安装部署](/docs/zh-cn/getting-started/installation/)。
