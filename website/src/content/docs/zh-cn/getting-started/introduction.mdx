CDelivery 是自托管的应用运维平台。你提供服务器和容器镜像，通过控制台部署应用、配置访问入口、观察运行状态，并按需要接入自动检查、定时任务和 AI 助手。

## 先理解四个对象

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| 服务器 | 提供计算资源及本地存储的机器 | 一台 Linux 云服务器 |
| 分组 | 组织应用并提供组内通信网络 | `demo` |
| 应用 | 镜像、配置和期望运行方式的组合 | `hello-web` |
| 副本 | 应用实际运行的实例 | 两个相同的 Web 容器 |

分组便于组织和组内通信，不是按用户隔离数据的权限边界。Reader 可以读取各分组的共享信息；不要把将应用放入另一个分组当作保密措施。

## 从哪里开始

1. 阅读[安装前准备](/docs/zh-cn/getting-started/requirements/)，确认系统、网络和访问方式。
2. 完成[安装与首次设置](/docs/zh-cn/getting-started/installation/)，创建首个管理员。
3. 按[部署第一个应用](/docs/zh-cn/getting-started/first-app/)运行 Nginx，验证完整部署链路。
4. 阅读[控制台导览](/docs/zh-cn/getting-started/console/)，找到配置、日志和平台管理入口。

首次使用只需完成安装与一个应用部署。域名、HTTPS、Insight、消息渠道和 AI 模型按实际需要配置。

## 运行应用与维护平台

日常应用操作包括更换镜像、调整资源、扩缩容、查看日志、配置 XHealth 和 XJob。服务器加入、分组管理、账户管理及平台组件配置则属于管理员职责。

| 角色 | 主要权限 |
| --- | --- |
| Reader | 读取共享信息，管理自己的账户与 API 密钥 |
| Operator | 另可执行应用、XHealth、XJob 和 Guardian 的运维操作 |
| Admin | 另可管理服务器、分组、用户及平台设置 |

详细边界见[角色与权限](/docs/zh-cn/administration/accounts/roles/)。API 密钥还具有角色上限；AI 对话沿用绑定用户的权限，自动值班使用单独配置的角色。

## 如何判断应用可用

部署提交成功只表示配置已被接受。还需要确认副本运行、应用监听端口正确，并从预期的客户端访问业务入口。运行状态、XHealth 检查结果和公网访问结果分别反映不同环节。

应用需要保存数据时，在创建前阅读[数据持久化](/docs/zh-cn/guides/apps/persistence/)。容器内未挂载的数据不会因为平台能够重启应用就自动获得持久化保障。
