CDelivery 主程序、Pingress、Insight、Insight Agent 和数据卷管理组件分别管理版本，需分别更新。

## 更新前检查

以 Admin 打开对应组件设置，查看当前版本和可用版本。阅读发布说明，确认目标机器能拉取镜像，预留更新时间，并按业务存储方案完成数据备份。

平台当前按发布目录提供最新版本，更新请求要求目标为对应组件的最新版本。控制台不提供任意历史版本选择或通用降级按钮。

## 执行与验证

<Steps>

1. 在**设置 → CDelivery**选择可用的新版本并确认更新。
2. 等待主程序重启，管理页面可能短暂不可用。
3. 重新打开页面，确认当前版本已变化。
4. 检查服务器、应用、事件和 API/MCP 连接。
5. 如其他组件也有更新，分别进入其设置完成并验证。

</Steps>

Pingress 更新后检查实际域名与 HTTPS；Insight 更新后确认新日志和指标继续出现；采集器更新后检查服务器报告是否恢复；数据卷管理更新后验证数据卷列表读取。

平台重启后，重新获取服务器加入凭证。

使用文本机密数据的应用在下一次部署配置变更时采用平台随附的运行时。平台升级本身不会重启这些应用；仅保存未变配置、修改描述、扩缩容或普通重启时，仍使用原有运行时；应用回滚则恢复之前的版本。

## 排障

“无法获取最新版本”意味着发布元数据不可用，不能据此判断已经是最新版。检查服务器到发布服务的网络，再重新查看。

镜像无法拉取时核对网络、架构与发布版本；更新后版本未变化时检查服务任务和事件。应用的[发布回滚](/docs/zh-cn/guides/release-safety/rollback/)针对应用配置，不是平台版本或业务数据的恢复工具。失去登录能力时参阅[恢复管理访问](/docs/zh-cn/administration/platform/recovery/)。
