卸载会删除平台管理资源、应用定义、账户和凭证，保留所有数据卷及卷说明。
</Aside>

## 卸载

在管理服务器上准备 Docker CLI 和 jq，选择本机 Docker Unix socket。先记录应用配置、镜像、卷与服务器的对应关系，并完成业务数据备份。卸载期间停止创建或重建资源。

在交互终端中运行：

```sh
curl -fsSL https://cdelivery.dev/uninstall.sh | sh
```

核对脚本显示的 Docker 地址和待删除资源，输入 `y` 或 `Y` 并按回车确认。直接回车、输入其他内容或按 Ctrl+C 均可取消。没有待删除资源时，脚本直接退出，无需确认。

脚本先停止主程序，再删除带有平台管理标记的资源。报告完成前，最多等待 120 秒，确认受管网络从本机 Docker 网络列表中消失；超时则列出剩余网络并报错退出。它不会卸载 Docker、擦除本地卷或替你删除外部 DNS、对象存储和服务商账户。

## 验证与失败处理

检查所列管理资源是否已移除，并确认要保留的数据卷仍在原服务器。容器清理是异步的；离线服务器上的容器是否退出无法在此时确认，需要恢复连接后单独核查。

某一步删除失败时，脚本停止并提示错误。先修复占用、连接或权限问题，再重新运行同一命令，重新预览并确认。不要在卸载尚未结束时重新安装或手工创建同名资源。

若还要删除业务卷，必须另行确认数据不再需要。重新安装会建立新的管理数据，原卷的恢复和重新挂载需要根据业务备份与记录完成。
