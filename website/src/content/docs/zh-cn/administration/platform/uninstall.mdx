卸载会删除平台管理资源、应用定义、账户和凭证。脚本保留所有数据卷及卷说明，但保留卷不等于能够一键恢复原平台。

## 准备与预览

在管理服务器上准备 Docker CLI 和 jq，选择本机 Docker Unix socket。先记录应用配置、镜像、卷与服务器的对应关系，并完成业务数据备份。卸载期间停止创建或重建资源。

下载官网脚本后先预览：

```sh
curl -fsSLo /tmp/cdelivery-uninstall.sh https://cdelivery.dev/uninstall.sh
sh /tmp/cdelivery-uninstall.sh
```

不带参数只列出选中的服务、配置、凭证、网络和平台调度标签，不删除资源。核对当前 Docker 地址与资源名单，避免在错误部署上执行。

## 执行卸载

确认预览符合预期后执行：

```sh
sh /tmp/cdelivery-uninstall.sh --yes
```

脚本先停止主程序，再删除带有平台管理标记的资源。它不会卸载 Docker、擦除本地卷或替你删除外部 DNS、对象存储和服务商账户。

## 验证与失败处理

检查所列管理资源是否已移除，并确认要保留的数据卷仍在原服务器。容器清理是异步的；离线服务器上的容器是否退出无法在此时确认，需要恢复连接后单独核查。

某一步删除失败时，脚本停止并提示错误。先修复占用、连接或权限问题，再重新运行 `--yes`。不要在卸载尚未结束时重新安装或手工创建同名资源。

若还要删除业务卷，必须另行确认数据不再需要。重新安装会建立新的管理数据，原卷的恢复和重新挂载需要根据业务备份与记录完成。
