数据卷属于具体服务器。同名数据卷出现在不同服务器上时，也不是同一份数据。删除应用会保留数据卷，删除数据卷才会移除对应的本地数据。

## 启用与创建

<Steps>

1. 以 Admin 启用数据卷管理组件；该组件使用独立的 cdelivery-agent 镜像。
2. 打开服务器详情中的数据卷页面。
3. 创建数据卷，填写名称和可选说明。名称遵循平台命名规则，说明最多 256 个字符。
4. 创建[有状态应用](/docs/zh-cn/guides/apps/persistence/stateful/)，选择同一服务器，将数据卷挂载到镜像要求的数据目录。
5. 写入测试数据并重启应用，确认数据仍存在。

</Steps>

## 查看容量

列表可查询数据卷大小，并显示服务器的总空间与可用空间。大小查询需要遍历数据，较大的数据卷可能花费更长时间；未查询或未返回大小不等于数据卷为空。

平台内部保留的数据卷不作为普通业务数据卷管理。数据卷说明用于记录用途。

## 删除与排障

<Aside type="caution">
删除数据卷会移除对应的本地数据；删除应用会保留数据卷。
</Aside>

如果数据卷说明保存失败，刷新列表后为已创建的数据卷补充说明。

删除前确认相关应用已停止使用数据卷，并有可恢复的业务备份。被容器占用时，先检查引用和异步退出状态，再重新删除。

无法列出数据卷时，检查目标服务器是否在线、数据卷管理组件是否启用并正常运行。停用数据卷管理组件会影响管理能力，不会自动删除业务数据卷。数据卷不存在时核对服务器 ID 和数据卷名称；不要在另一台机器新建同名数据卷来代替恢复数据。

数据迁移、数据库一致性备份和跨服务器复制需要由业务存储方案完成。继续阅读[数据持久化](/docs/zh-cn/guides/apps/persistence/)。
