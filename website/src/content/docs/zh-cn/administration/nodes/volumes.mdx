数据卷属于具体服务器。同名卷出现在不同服务器上时，也不是同一份数据。删除应用会保留卷，删除卷才会移除对应的本地数据。

## 启用与创建

1. 以 Admin 启用数据卷管理组件；该组件使用独立的 cdelivery-agent 镜像。
2. 打开服务器详情中的数据卷页面。
3. 创建卷，填写名称和可选说明。名称遵循平台命名规则，说明最多 256 个字符。
4. 创建[有状态应用](/docs/zh-cn/guides/apps/persistence/stateful/)，选择同一服务器，将卷挂载到镜像要求的数据目录。
5. 写入测试数据并重启应用，确认数据仍存在。

卷创建和说明保存是两个步骤。如果提示说明保存失败，先刷新列表确认卷是否已经创建，再修正说明，避免误判为整个操作未发生。

## 查看容量

列表可查询卷大小，并显示服务器的总空间与可用空间。大小查询需要遍历数据，较大的卷可能花费更长时间；未查询或未返回大小不等于卷为空。

平台内部保留的卷不作为普通业务卷管理。卷说明帮助识别用途，但不构成备份，也不证明当前没有应用使用它。

## 删除与排障

删除前确认相关应用已停止使用卷，并有可恢复的业务备份。不要仅因应用已删除就认为卷中数据无价值。被容器占用时，先检查引用和异步退出状态，再重新删除。

无法列出卷时，检查目标服务器是否在线、卷管理组件是否启用并正常运行。停用卷管理组件会影响管理能力，不会自动删除业务卷。卷不存在时核对服务器 ID 和卷名；不要在另一台机器新建同名卷来代替恢复数据。

数据迁移、数据库一致性备份和跨服务器复制需要由业务存储方案完成。继续阅读[数据持久化](/docs/zh-cn/guides/apps/persistence/)。
