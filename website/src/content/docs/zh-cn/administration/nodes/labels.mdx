标签把具备相同用途的服务器组织成可选择的运行范围。例如，为两台应用服务器添加 `web`，为存储机器添加 `storage`。

## 添加标签

1. 以 Admin 从服务器列表打开目标机器。
2. 添加所需标签并保存。
3. 在其他同类服务器上使用相同标签。
4. 在应用的[服务器选择](/docs/zh-cn/guides/apps/placement/)或组件设置中选择该标签。
5. 检查实际任务落点和资源是否满足需求。

每台服务器最多 32 个调度标签。标签使用 1–16 个小写字母、数字或连字符，不能以连字符开头或结尾，也不能使用保留名称。标签表达成员关系，不提供任意键值查询或复杂条件表达式。

## 变更的影响

同一个标签可以属于多台机器。删除标签会改变依赖该标签的任务可选范围；如果没有可用机器，任务可能无法启动。添加标签之前也应确认该机器的容量、镜像架构、网络和数据条件。

固定服务器的应用不因相同标签而迁移。标签不会同步本地卷；需要本地数据的工作负载应遵循[有状态应用](/docs/zh-cn/guides/apps/persistence/stateful/)的部署方式。

## 验证与排障

保存后重新打开服务器检查标签，再查看应用的实际副本分布。若任务一直等待，检查是否至少有一台 Ready、可调度且资源充足的匹配机器，以及每台服务器的副本上限。

通过 API 更新标签时，`labels` 是完整替换集合，空数组会清空平台调度标签。先读取当前集合再修改，避免把需要保留的标签遗漏。
