服务器列表展示机器名称、角色、状态、CPU、内存及调度标签。主机名可能重复，判断具体机器时同时核对地址和服务器 ID。

## 加入服务器

1. 以 Admin 打开服务器列表，选择 Worker 或 Manager 的加入命令。
2. 在目标服务器检查[安装要求](/docs/zh-cn/getting-started/requirements/)，确认它能访问管理地址和服务器间通信端口。
3. 在目标机器运行页面给出的命令。命令中包含加入凭证，不要公开分享。
4. 刷新列表，确认新服务器出现、状态 Ready，并核对角色和地址。
5. 按用途添加[标签](/docs/zh-cn/administration/nodes/labels/)，再部署应用。

Worker 承载工作负载；Manager 还参与管理。加入凭证有效 30 分钟，可在有效期内复用。平台重启后应重新获取；签发者权限变化也可能使凭证失效。过期时刷新页面生成新命令，不要反复尝试旧凭证。

## 理解状态

| 字段 | 含义 |
| --- | --- |
| Ready / Down / Disconnected | 当前运行或连接状态 |
| Active | 可接收调度 |
| Pause | 不接收新的任务 |
| Drain | 排空任务的调度状态 |
| Reachable / Unreachable | Manager 的管理连接状态 |
| 采集器告警 | 观测报告可能不新鲜，需单独检查采集链路 |

状态展示不意味着控制台提供所有状态切换操作。资源总量也不等于当前剩余容量，结合[服务器指标](/docs/zh-cn/guides/observability/metrics/server/)查看。

## 移除服务器

当前移除操作不替你完成应用迁移、数据备份或服务器排空。先检查固定在该服务器上的有状态应用、数据卷和平台组件，以及其余服务器的容量。Manager 的移除还应保持管理能力可用。

确认依赖已处理后再删除。移除记录不擦除原机器上的本地卷，也不能确认离线机器上的容器已经退出。重新加入后服务器 ID 可能变化，应重新核对固定服务器配置和标签。

加入失败时依次检查地址、凭证有效期、Docker 状态、端口与防火墙；不要只根据浏览器能打开控制台判断服务器间通信正常。
