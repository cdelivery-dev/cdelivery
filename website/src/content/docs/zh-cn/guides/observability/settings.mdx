Insight 负责观测数据的存储与查询，采集组件提供服务器及容器数据。配置需要 Admin，入口位于控制台的 Insight 页面。

## 首次启用

1. 选择可用的服务端与采集端版本。
2. 选择存储类型，并填写对应位置与凭据。
3. 配置服务端部署位置。
4. 设置保留天数、采样间隔及缓冲数据落盘间隔。
5. 保存后检查服务端和采集端的实际运行状态。
6. 打开服务器及应用指标，验证数据开始出现。

## 存储选项

| 类型 | 需要准备 |
| --- | --- |
| 本地 | 可持久运行的目标服务器及本地存储容量 |
| S3 | 区域、存储桶、访问密钥和秘密密钥 |
| S3 兼容 | 额外填写服务端点，并使用该服务要求的区域 |
| GCS | 存储桶与服务账户凭据 JSON |
| Azure | 容器名称、账户名称和账户密钥 |

按存储服务要求授予读写所需权限，并保管凭据。首次启用后，存储位置和类型受到限制，主要允许更新区域及认证信息；本地存储的部署位置也固定。不要把编辑表单当作自动数据迁移功能。

## 时间设置

| 设置 | 界面初始值 | 范围或含义 |
| --- | --- | --- |
| 保留期限 | 30 天 | 1–3650 天 |
| 采样间隔 | 5 秒 | 1–60 秒 |
| 落盘间隔 | 3 分钟 | 控制缓冲数据写入存储的时间，按界面单位填写 |
| 文件系统采样 | 5 分钟 | 独立于普通采样间隔 |

更短采样间隔会增加数据量。保留期限越长，需要的存储通常越多。缩短保留期限前，确认旧数据可以被清理；之后再调长不会恢复已删除的数据。

## 新数据为什么可能稍后出现

采样、日志批量提交、缓冲写入和不同实例之间的数据同步是不同环节。固定服务器部署可查询该实例的缓冲数据；使用标签部署时，还可能等待写入及跨实例同步。

因此，5 秒采样不等于每个查询入口都保证在 5 秒内看到数据。排障时检查实际配置和各组件状态。

## 修改、停用与排障

修改设置后核对保存结果、组件版本、存储连接和新数据。停用组件会影响依赖它的观测能力，应先确认业务对日志、指标、自动扩缩容和 AI 分析的使用。

存储认证失败时，核对目标位置和密钥作用域；更换账户或位置后不要假设旧秘密字段仍可复用。查询空结果时检查时间范围和保留期限，查询失败时保留原始错误继续排查。
