Insight 负责观测数据的存储与查询，采集组件提供服务器及容器数据。配置需要 Admin，入口位于控制台的 Insight 页面。

服务器和容器指标依赖采集组件；历史观测数据依赖 Insight 存储。应用日志还受所选日志驱动影响；启用 Insight 不会补采旧日志。

访问日志记录经过 Pingress 的请求。

## 首次启用

<Steps>

1. 选择可用的服务端与采集端版本。
2. 选择存储类型，并填写对应位置与凭据。
3. 配置服务端部署位置。
4. 设置保留天数、采样间隔及缓冲数据落盘间隔。
5. 保存后检查服务端和采集端的实际运行状态。
6. 打开服务器及应用指标，验证数据开始出现。

</Steps>

## 存储选项

| 类型 | 需要准备 |
| --- | --- |
| 本地 | 可持久运行的目标服务器及本地存储容量 |
| S3 | 区域、存储桶、访问密钥和秘密密钥 |
| S3 兼容 | 额外填写服务端点，并使用该服务要求的区域 |
| GCS | 存储桶与服务账户凭据 JSON |
| Azure | 容器名称、账户名称和账户密钥 |

按存储服务要求授予读写所需权限，并保管凭据。首次启用后，存储位置和类型受到限制，主要允许更新区域及认证信息；本地存储的部署位置也固定。

## 时间与保留

| 设置 | 界面初始值 | 范围或含义 |
| --- | --- | --- |
| 保留期限 | 90 天 | 1–3650 天 |
| 采样间隔 | 5 秒 | 1–60 秒 |
| 落盘间隔 | 3 分钟 | 控制缓冲数据写入存储的时间，按界面单位填写 |
| 文件系统采样 | 5 分钟 | 独立于普通采样间隔 |

更短采样间隔会增加数据量。保留期限越长，需要的存储通常越多。

<Aside type="caution">
缩短保留期限前，确认旧数据可以被清理；之后再调长不会恢复已删除的数据。
</Aside>

采样、日志批量提交、缓冲写入和不同实例之间的数据同步是不同环节。固定服务器部署可查询该实例的缓冲数据；使用标签部署时，还可能等待写入及跨实例同步。

## 验证与排障

先选覆盖故障发生时间的窗口，再逐步缩小。比较日志、指标和事件时，确保它们针对同一应用、同一服务器和相近时间。

大范围图表会按时间桶聚合，图上的一个点不一定等于单次采样。应用或服务器刚创建、重新启动、变更配置后，也可能尚无完整数据窗口。

1. 核对目标对象和时间范围。
2. 检查 Insight 及采集组件状态。
3. 检查对应日志驱动或 Pingress 是否实际产生该类数据。
4. 核对存储连接和保留期限。
5. 查看页面给出的查询错误，区分查询失败和空结果。

从事件定位变更时间，用指标确认影响范围，再用对应日志检查具体错误。

修改设置后核对保存结果、组件版本、存储连接和新数据。停用组件会影响依赖它的观测能力，应先确认业务对日志、指标、自动扩缩容和 AI 分析的使用。

存储认证失败时，核对目标位置和密钥作用域；更换账户或位置后不要假设旧秘密字段仍可复用。查询失败时保留原始错误继续排查。
