应用指标用于观察资源消耗和请求表现。打开应用的指标页面，选择覆盖问题时间的范围，再结合当前副本和发布事件分析。

## 资源指标

| 类别 | 重点关注 |
| --- | --- |
| CPU | 使用量、限制、节流及压力 |
| 内存 | 当前使用、工作集、限制、交换及内存不足相关指标 |
| 磁盘 I/O | 读写速率、操作次数及 I/O 压力 |
| 网络 | 接收、发送速率及 TCP 重传 |
| 进程 | 进程数量和限制 |
| 副本 | 期望与实际运行情况 |

图表可用字段取决于采集环境。未提供或无法计算的值不能直接按零解释。

## 请求指标

经过 Pingress 的请求可以提供请求率、错误比例、总耗时和上游首字节时间等信息。没有经过 Pingress 的流量，不会自动出现在这组请求指标中。

延迟百分位表示选定窗口内的分布特征。高百分位升高时，应结合请求量、错误状态和应用日志判断，而不是只看平均值。

## 单位与聚合

CPU 使用量可能以核数或百分比展示，内存以字节量或比例展示。阅读时先看图表单位、对象范围和对应限制，不能把多核服务器上的数值直接当作单核百分比。

扩大时间范围后，图表会使用更宽的时间桶。最小、平均、最大值与百分位具有不同含义；缩小窗口有助于观察短暂峰值。

指标查询时间跨度最长为 31 天，实际可用历史还取决于保留期限。选择更久以前的时间，不会恢复已被清理的数据。

## 一个排查示例

应用响应变慢时：

1. 找到延迟开始变化的时间。
2. 对照发布、扩缩容和配置事件。
3. 查看 CPU 节流、内存压力及 I/O 指标。
4. 查看同一时间的访问日志和应用错误。
5. 核对是否所有副本都受到影响，以及它们所在服务器是否异常。

CPU 较高可能是原因，也可能是业务负载增加的结果。单个相关指标不能独立证明因果关系。

## 数据缺失

先确认 [Insight 与采集设置](/docs/zh-cn/guides/observability/settings/)、实际副本和时间范围。刚创建或重启的实例需要积累有效样本；发生采集间断时应保留缺失含义。

决定修改[资源限制](/docs/zh-cn/guides/apps/resources/)或[自动扩缩容](/docs/zh-cn/guides/apps/scaling/)前，至少观察正常负载和代表性峰值。
