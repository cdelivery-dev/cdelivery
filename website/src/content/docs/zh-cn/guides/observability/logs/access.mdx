访问日志记录经过 Pingress 的请求，帮助区分入口、路由和应用响应问题。直接访问应用发布端口的请求不经过 Pingress，因此不应期待在这里看到它。

## 查看访问记录

应用配置域名后，可在应用日志页选择访问日志来源。先选时间范围，再用界面提供的筛选条件缩小问题请求。

记录列表展示请求时间、方法、路径、状态、耗时和客户端地址。展开一条记录可以查看更详细的信息。

| 字段 | 用途 |
| --- | --- |
| 域名与路径 | 确认请求访问的入口 |
| 状态及结果 | 区分实际 HTTP 响应与入口处理结果 |
| 目标端口与服务 | 核对匹配到的应用目标 |
| 节点 | 找到处理该请求的 Pingress 实例 |
| 请求和响应字节数 | 了解流量大小 |
| 上游首字节时间 | 观察等待上游开始响应的时间 |
| 错误 | 定位连接或代理处理失败 |

某些失败发生在完整请求信息可用之前，因此部分字段可能为空。

## 常见分析方式

**请求没有记录**：先检查 DNS 是否指向这个入口、客户端是否绕过 Pingress，以及采集和存储是否正常。

**请求未命中预期应用**：核对域名、路径前缀、请求头和 Cookie 条件。应用范围查询只展示归属于该应用的记录，未匹配请求需在相应入口范围继续排查。

**上游失败**：检查目标端口、容器监听地址、实际副本和应用日志。入口能够收到请求不代表上游已经可用。

**请求较慢**：结合整体耗时、上游首字节时间和应用指标分析，不能仅凭一条慢请求判断服务器资源不足。

## 客户端地址

Pingress 记录直接连接方的地址，并据此设置转发请求头。存在 CDN、其他代理或网络地址转换时，记录的地址可能不是最终用户原始地址。

IPv6 网桥及真实客户端地址相关检查见[网络常见问题](/docs/zh-cn/guides/networking/faq/)。应用自身连接的对端通常是 Pingress，应区分连接地址和转发请求头。

## 数据限制

访问记录依赖 Pingress 产生数据及 Insight 的可用性和保留设置。日志迟到、保留到期和查询失败需要分别识别。

路径和查询信息可能包含业务标识或其他敏感内容。对外分享记录前检查并脱敏，不要把请求日志当成可以公开传播的数据。
