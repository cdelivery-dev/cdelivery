打开应用的日志页，先选择正确的来源和时间范围。应用、XHealth、XJob 与 Guardian 的输出属于不同运行资源，排查时不要把它们混在一起。

## 选择来源

| 来源 | 用途 |
| --- | --- |
| 应用 | 正式应用进程的标准输出和标准错误 |
| XHealth | 周期性检查的执行输出 |
| XJob | 某个计划任务的输出 |
| Guardian 应用 | 候选配置运行时的输出 |
| Guardian 检查 | 候选验证任务的输出 |

可用选项取决于实际存在的资源和日志配置。历史资源已经清理或日志已经轮转时，不一定还能查询到原记录。

## 查看步骤

1. 打开目标应用的日志页面。
2. 选择对应来源；XJob 应明确到具体任务。
3. 选择覆盖问题发生时间的范围。
4. 按页面提供的条件筛选并翻页。
5. 结合时间、来源和完整错误上下文判断问题。

程序写入容器内部普通文件的日志，不会自动等同于标准输出日志。需要在这里查看时，应按应用自身的配置将所需输出写到标准输出或标准错误。

## 日志驱动

应用配置中可以选择：

| 模式 | 行为 |
| --- | --- |
| 跟随宿主机 | 使用宿主机当前日志配置，保留和可读取能力由该配置决定 |
| JSON 文件 | 为容器日志设置文件大小和数量上限 |
| Insight | 将应用日志交给 Insight，依赖对应服务和存储 |

切换到 JSON 文件时，界面初始值为每个文件 10 MiB、保留 5 个文件。文件数量允许 1–100，每个文件最大为 1 GiB。按业务日志量调整，避免轮转过快或占满磁盘。

修改日志驱动会影响后续运行容器，不会自动补采之前丢失或已清理的日志。

## 空日志与查询错误

没有记录时，先确认程序是否实际输出到标准输出、时间范围是否正确、对应任务是否运行过，再检查日志驱动与采集服务。

查询失败时保留页面错误信息，检查目标服务器、存储或组件状态。不要把“查询失败”写成“没有错误日志”。

查看早期故障时，还要考虑本地轮转和 Insight 保留期限。历史数据超出保留范围后不能仅靠重新打开页面恢复。

## 分享日志

保留错误前后的必要上下文和时间，但移除访问令牌、密码、用户个人信息及业务敏感内容。平台不能保证自动识别应用写入日志中的所有秘密。
