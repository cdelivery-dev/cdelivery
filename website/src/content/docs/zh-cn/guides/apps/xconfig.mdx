XConfig 将上传的文件作为配置交给应用容器，例如 Nginx 配置或应用启动时读取的设置文件。它适合部署配置，不适合数据库、上传目录或持续写入的数据。

## 使用条件

- 你具有 Operator 或 Admin 权限。
- 应用采用允许 XConfig 的无状态部署方式。
- 已确定容器内需要读取文件的绝对路径。
- 单个文件非空，大小不超过 1,023,999 字节。

使用本地数据挂载的有状态应用不能同时使用 XConfig。先根据[数据持久化](/docs/zh-cn/guides/apps/persistence/)选择部署方式。

## 添加配置文件

1. 打开应用创建页或配置页中的文件与存储设置。
2. 在配置文件列表添加一项。
3. 填写容器内目标文件路径，例如 `/etc/nginx/conf.d/default.conf`。
4. 选择本地文件，确认该行出现在待保存列表。
5. 保存整个应用配置，等待更新完成。

对话框中的确认只是完成本次表单编辑，仍需提交应用配置才能真正部署。目标应为文件路径，不能以斜杠结尾，也不能把目录本身当作一个文件挂载。

## 查看和保留已有文件

已使用的配置会显示平台记录的文件名称，并提供下载入口。编辑其他应用设置时，保留原有行即可继续引用已有文件，无需每次重新上传。

这些引用属于当前应用使用的配置，不是供任意应用按名称共享的全局配置库。不要通过猜测其他应用的配置名称来复用文件。

修改内容和改变目标路径的操作见[配置挂载与更新](/docs/zh-cn/guides/apps/xconfig/mounting/)。

## 配置、秘密和数据的边界

| 内容 | 适合的方式 |
| --- | --- |
| Nginx、应用启动配置 | XConfig |
| 少量运行参数 | 环境变量 |
| 数据库文件、业务上传 | 持久化数据卷 |
| 仓库认证 | 镜像凭据字段 |

配置文件可能通过共享读取能力被查看或下载，不要假设文件中的密码会被自动脱敏。

XConfig 也不是长期备份库。保留你自己的配置源文件或版本库；删除引用后，平台可能清理不再被运行资源使用的配置。

## 上传失败时

检查文件是否为空或超过大小限制、目标路径是否合法、是否与其他挂载冲突，以及应用是否已选择本地数据模式。上传并保存成功后，再验证应用实际读取的文件路径；文件存在不代表内容语法正确。
