配置文件通过目标路径进入容器。上传新内容会形成新的部署配置，不能把它视为直接修改正在运行的容器文件。

## 准备一个完整配置

以下文件可用于 Nginx 入门应用，目标路径为 `/etc/nginx/conf.d/default.conf`：

```nginx
server {
    listen 80;
    location / {
        default_type text/plain;
        return 200 "Hello from CDelivery\n";
    }
}
```

在本地保存文件后，通过 [XConfig](/docs/zh-cn/guides/apps/xconfig/)上传。镜像需要包含 Nginx，并使用会加载该目录的配置。可以保留入门教程的 TCP 80 → 8080 端口映射。

## 替换现有内容

1. 打开应用配置，在配置文件列表编辑现有项。
2. 选择新的本地文件。当前界面在编辑已有项时固定目标路径。
3. 确认对话框，然后保存应用配置。
4. 查看更新或 Guardian 验证状态。
5. 请求应用入口，确认响应已经来自新配置。

改变目标路径时，删除旧行，再添加新路径的文件。保存前确认列表仍包含需要保留的其他文件。移除一行并保存后，该文件将不再出现在新的应用配置中。

## 更新如何生效

未启用 Guardian 时，配置变化按应用更新策略部署；启用且符合条件时，新配置先进入验证流程。验证失败不能解释为新内容已在正式实例生效。

配置更新可能替换容器，不能假设进程会收到某个自动“热加载”信号。应用能否热加载属于应用自身行为。需要持续写入的文件也不应由 XConfig 承担。

## 验证挂载

| 检查项 | 应确认的结果 |
| --- | --- |
| 目标路径 | 与应用实际读取位置一致 |
| 应用日志 | 没有语法错误、权限错误或文件不存在 |
| 副本状态 | 更新完成，未持续失败或重启 |
| 业务响应 | 新设置确实生效 |
| 健康检查 | 使用相关路径的检查通过 |

仅改变本地源文件不会自动更新已上传的版本。每次发布新内容都需要重新上传并保存。

## 失败处理

语法错误时先修正源文件再上传。错误路径时核对镜像的配置布局。Guardian 拒绝推广时查看候选应用及检查日志，参见[发布验证](/docs/zh-cn/guides/release-safety/)。

需要回到旧配置时，使用实际可用的[回滚方式](/docs/zh-cn/guides/release-safety/rollback/)或重新上传保存好的源文件。不要依赖被移除的配置引用永远保留。
