应用将镜像、启动参数、网络、资源和存储组合为期望的运行配置。控制台负责提交和展示这些配置，实际运行结果还需要通过副本状态、日志和业务访问确认。

## 操作前的选择

| 需要决定的事项 | 为什么要提前考虑 |
| --- | --- |
| 所属分组 | 决定应用组织及组内通信，控制台不提供应用改名或移动分组操作 |
| 是否保存业务数据 | 本地数据挂载需要在创建时选择，不能在普通应用创建后直接切换为该模式 |
| 镜像与启动方式 | 需要知道镜像监听端口、启动命令及必需环境变量 |
| 访问入口 | 内部通信、直接发布端口、域名访问是不同的配置 |
| 资源与副本 | 每个副本都需要资源，更新期间也可能需要额外容量 |

Reader 可以查看共享信息。创建、修改、重启和删除应用需要 Operator 或 Admin；创建分组与管理服务器资源需要 Admin。

## 默认行为与验证

从空白表单创建时，应用默认固定一个副本，使用镜像默认命令和宿主机日志设置；没有额外资源预留或调度标签。默认更新策略为全部副本并行、先停止旧副本、观察 60 秒、失败比例阈值 0，失败动作是回滚。业务有连续服务要求时，创建后应检查[更新策略](/docs/zh-cn/guides/release-safety/update-strategy/)。

保存成功后先看实际副本，再看应用日志，最后验证客户端请求。配置无变化时，重复保存不会强制重新部署；需要替换运行容器时使用重启操作。

配置页面中的环境变量和文件内容不应被视作个人私密存储。平台只对明确识别的秘密字段脱敏，其他共享配置可能被具备读取权限的账户看到。

需要业务级检查时配置 [XHealth](/docs/zh-cn/guides/release-safety/xhealth/)；需要在推广新配置前验证候选实例时，再了解 [Guardian](/docs/zh-cn/guides/release-safety/)。
