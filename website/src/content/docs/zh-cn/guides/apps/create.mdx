创建应用需要 Operator 或 Admin，并且目标分组已经存在。先准备镜像、容器端口和必需配置；需要持久化数据时，还应由管理员准备目标服务器的数据卷。

## 从空白配置开始

1. 在侧栏找到目标分组，点击创建应用。
2. 填写唯一的应用名称和可选描述。名称在整个平台中唯一，不能只依赖分组区分重名应用。
3. 填写镜像；私有镜像在镜像设置中填写用户名和密码或令牌。
4. 按镜像要求配置启动命令、环境变量、端口和文件。
5. 设置副本、资源和调度条件；简单无状态应用可先使用默认值。
6. 检查全部配置后创建，等待应用概览显示运行结果。

名称为 1–16 个小写字母、数字或连字符，首尾不能是连字符；平台保留名称不能使用。描述最多 500 个字符。控制台不提供创建后的应用改名操作。

## 创建时应明确的设置

| 设置 | 说明 |
| --- | --- |
| 镜像 | 使用仓库实际存在的镜像与标签 |
| 启动命令 | 留空使用镜像默认值；自定义命令需要包含可执行程序 |
| 环境变量 | 按镜像文档填写，值不自动进行 shell 展开 |
| 发布端口 | 容器内端口与客户端访问端口分别填写 |
| 文件与存储 | 选择配置文件或本地数据方式，提前确认有状态限制 |
| 资源与副本 | 按单个副本计算资源，确认服务器有足够容量 |

首次练习可使用[完整 Nginx 示例](/docs/zh-cn/getting-started/first-app/)。

## 使用数据库模板

创建页面提供 PostgreSQL、MySQL 和 MariaDB 模板。模板会预填镜像、端口、环境变量和生成的密码，但仍需你选择目标服务器与数据卷。

1. 选择数据库模板，确认镜像版本和生成的环境变量。
2. 保存生成的密码到你自己的凭据管理工具。
3. 选择已准备的数据卷及模板对应的数据目录。
4. 如果数据库只供同分组应用访问，移除不必要的对外发布端口。
5. 创建后检查数据库初始化日志，再使用客户端验证连接。

模板是部署配置的起点。已有数据的格式兼容、数据库升级和备份仍需遵循数据库自身的规则，详见[有状态应用](/docs/zh-cn/guides/apps/persistence/stateful/)。

## 验证与失败处理

副本进入运行状态后，检查业务响应或数据库连接。镜像下载失败时先核对仓库与凭据；等待调度时检查资源、标签及目标服务器；进程反复退出时检查日志、命令、环境变量和挂载路径。

创建请求超时或返回错误后，先回到应用列表确认资源是否已经出现，再决定是否重试。不要通过连续创建相同名称来判断操作是否成功。
