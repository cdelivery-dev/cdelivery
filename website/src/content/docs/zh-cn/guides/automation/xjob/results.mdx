XJob 列表与详情显示当前或最近一次执行状态，以及上次、下次执行时间。当前界面不是完整的历史执行列表；需要较早的证据时，应在日志和事件的保留范围内查找。

API 字段 `last_run` 是观测到的最近任务创建时间，不是结束时间。任务记录缺失不能证明成功。超时停止会记录 `XJobFailed` 事件；任务记录已消失时，应结合事件与日志排查。

## 解释结果

| 状态 | 说明 |
| --- | --- |
| 等待 | 尚未得到本轮完成结果 |
| 运行中 | 命令仍在执行 |
| 通过 | 命令成功退出 |
| 失败 | 命令失败，查看错误和日志 |
| 已结束但无成功结论 | 不能视为业务执行成功，需要进一步检查 |

退出码成功只说明命令按自身定义返回成功。关键业务任务还应验证实际输出或数据变化，例如文件确实生成、同步记录确实出现。

## 查看日志

1. 打开任务所属应用的日志页面。
2. 选择对应 XJob 任务来源。
3. 将时间范围定位到任务开始和结束附近。
4. 根据错误信息区分命令、依赖、网络及业务问题。

日志可用性取决于应用日志驱动、采集状态及保留设置。没有日志不等于任务没有执行，也不等于执行成功。

## 常见问题

| 现象 | 检查内容 |
| --- | --- |
| 命令不存在 | 应用镜像是否包含程序、脚本路径及执行权限 |
| shell 表达式没有生效 | 是否显式使用 shell，变量和引号是否正确 |
| 连接服务失败 | 同分组服务名称、内部端口、凭据及服务状态 |
| 下次执行时间不符 | 等待间隔、本轮结束时间及任务记录是否缺失 |
| 手动运行按钮不可用 | 当前是否仍有活动执行、是否具有操作权限 |
| 长时间不结束 | 命令是否会退出、外部请求是否挂起、任务是否适合独立应用 |

执行超时按配置生效，轮询和停止过程可能造成延迟。任务应具有明确结束条件，避免用无限循环充当调度工作。

## 失败后重试

先判断任务是否已完成部分写入，再决定是否手动重试。重新执行不会自动撤销上一轮副作用；去重、断点续作和数据一致性由实际业务命令负责。

保留任务名称、时间、完整错误和必要日志，分享前移除凭据。需要持续接收失败信息时，配置[通知渠道](/docs/zh-cn/guides/automation/im/notifications/)。
