邮件通知只需要 SMTP。要通过邮件与 AI 对话，还需配置 IMAP 和[模型](/docs/zh-cn/guides/automation/models/)。请为平台准备一个专用邮箱，并确认服务器能访问邮件服务商。

## 配置发送

1. 以 Admin 打开设置中的邮件渠道，填写平台邮箱地址。
2. 填写 SMTP 主机、端口和密码。邮箱地址同时作为登录用户名。
3. 端口 465 使用隐式 TLS；其他端口走服务端支持的加密升级连接。使用服务商明确支持的端口。
4. 保存后，在个人账户中启用邮件通知，检查账户邮箱是否正确。

部分服务商要求应用专用密码。例如 Google 的应用密码需要账户启用两步验证，且可能受组织策略限制，参阅[官方说明](https://support.google.com/accounts/answer/185833)。不能用一个不允许 SMTP 登录的普通密码代替。

## 配置接收

| 字段 | 填写方式 |
| --- | --- |
| IMAP 主机 | 服务商提供的收件服务器 |
| 端口 | 默认 993，使用隐式 TLS |
| 密码 | 对应平台邮箱的 IMAP 登录凭证 |
| authserv_id | 可信收件服务器写入 Authentication-Results 的认证服务器标识 |

CDelivery 读取 INBOX。首次连接或重建接收游标时从当前邮箱末尾开始，不会把历史邮件重新当作操作请求。配置完成后发送一封新邮件验证。

入站邮件的发件地址必须匹配现有 CDelivery 用户；可信认证结果还必须同时通过 DKIM 和 DMARC。只看到 From 地址正确并不足以通过验证。请从可信收件服务器实际写入的邮件头确定 authserv_id，不能随意填写发件人的域名。

## 验证与排障

用自己的账户邮箱发送一封新的纯文本邮件，询问应用状态。确认邮箱收到回复，且回复对应当前账户的权限。

| 现象 | 检查 |
| --- | --- |
| 保存失败 | SMTP/IMAP 地址、TLS、端口、登录凭证及出站网络 |
| 可以通知但不能对话 | IMAP、模型、发件地址、可信认证结果 |
| 新邮件不处理 | 是否进入 INBOX、是否在接收器启动之后收到 |
| 通知未收到 | 个人通知开关、垃圾邮件、服务商投递限制 |
| 换邮箱后认证失败 | 更新对应 SMTP 和 IMAP 密码，不能沿用旧地址的凭证 |

平台保存凭证后不会回显密码。地址、主机或端口变化时重新提供相应凭证。通知对象和角色规则见[通知设置与排障](/docs/zh-cn/guides/automation/im/notifications/)。
