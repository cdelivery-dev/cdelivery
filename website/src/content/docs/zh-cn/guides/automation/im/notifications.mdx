通知需要配置平台渠道、个人接收设置和通知对象。

## 配置顺序

<Steps>

1. Admin 在设置中启用邮件或消息渠道。
2. 每位用户在个人账户中填写自己的消息平台 ID，或确认账户邮箱。
3. 新账户的邮件通知和新绑定的消息通知默认开启，可在个人账户中关闭。
4. 如果需要 AI 值班分析，再配置模型与[自动值班](/docs/zh-cn/guides/automation/duty/)。
5. 在实际运维事件发生后核对事件、通知内容和接收对象。

</Steps>

解绑会清除对应通知订阅，重新绑定默认开启。重复保存绑定、直接更换 ID 或修改账户邮箱均保留当前通知开关。管理员配置或清除平台渠道不修改个人偏好。

不同消息平台的 ID 格式不同，参阅对应[渠道说明](/docs/zh-cn/guides/automation/im/)。显示名、群 ID 和机器人 ID 不能通用。

## 谁会收到通知

已订阅用户中，角色不低于值班角色的接收 AI 分析，其他用户接收原始告警。操作回执遵循同样的角色限制。

启用 AI 值班后，等待分析完成，每位接收者的每个渠道只发送一条通知。分析失败、取消、无有效内容或超过 60 秒预算时，发送原始告警。停用值班时直接发送原始告警。

重新启用值班时，不会补分析待处理事件。

值班通知使用值班配置中的通知语言；用户发起的 AI 对话跟随对话语言。停止自动值班不等于关闭所有普通运维告警。关闭个人通知也不等于删除消息平台绑定。

## 按链路排查

| 步骤 | 检查内容 |
| --- | --- |
| 事件是否产生 | 应用状态、检查结果与操作事件，不能仅凭没有通知判断系统正常 |
| 渠道是否可用 | 平台凭证、应用发布状态、发送权限、出站网络 |
| 接收人是否正确 | 当前账户的邮箱或不可变用户 ID |
| 是否订阅 | 个人邮件开关及各消息渠道开关 |
| 角色是否符合 | 当前用户角色与 AI 值班角色 |
| 平台是否接收 | 垃圾邮件、私聊限制、机器人访问范围、限流 |
| AI 是否执行 | 模型和自动值班配置、分析期间的错误 |

排查时记录发生时间、渠道、账户和相关事件。不要把机器人 Token、邮件密码或 API 密钥放入反馈内容。修改个人绑定后，先使用只读对话确认对应账户；不要依赖收到头像或显示名来判断权限绑定正确。
