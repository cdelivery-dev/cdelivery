AI 助手结合平台操作、日志、指标和事件回答运维问题。交互对话通过已配置的消息渠道进行；模型配置和渠道绑定是两个独立步骤。

## 开始对话

1. 管理员完成[模型配置](/docs/zh-cn/guides/automation/models/)。
2. 管理员接入一种[消息渠道](/docs/zh-cn/guides/automation/im/)。
3. 你在自己的账户中绑定该渠道的不可变用户 ID。
4. 向 Bot 发送一条只读问题，例如“检查 hello-web 当前副本和最近一次健康检查结果”。
5. 核对回复中的对象、时间和实际查询结果。

支持邮件接入时，管理员还需要配置接收邮件所需的 IMAP 及身份验证条件。仅配置 SMTP 发送通知不足以开启邮件对话。

## 提问方式

提供明确对象、时间和期望结果，可以减少无关查询。例如：

- “查看 hello-web 最近 30 分钟的错误日志，并与最近一次更新对照。”
- “比较这台服务器的内存压力与上面的应用重启时间。”
- “检查数据库连接失败的应用配置，先给出原因和修改建议。”

当需要执行写操作时，明确描述目标和范围。完成后到控制台核对状态及[操作事件](/docs/zh-cn/guides/observability/events/)，不要仅依据自然语言表述判断操作成功。

## 权限如何生效

对话使用绑定用户的实时权限。Reader 可以读取共享信息及管理自身资源；Operator 和 Admin 按各自角色执行更多操作。Bot 不会因为由管理员创建就让所有对话用户获得管理员权限。

绑定的是平台返回的不可变用户 ID，而不是昵称或群名称。填写他人的 ID 可能把你的权限和数据暴露给对应账户，必须自行核对，参见[消息与通知](/docs/zh-cn/guides/automation/im/)。

## 数据与判断边界

模型能够分析的内容取决于权限、可用工具、采集状态和保留时间。缺失指标或没有日志不能单独证明系统正常；要求助手区分观察到的事实、推测和未验证部分。

配置外部模型服务时，相关问题及被查询的上下文会用于模型请求。应按自己的数据要求选择提供商与服务端点。

## 对话与自动值班

对话由用户发起；[自动值班](/docs/zh-cn/guides/automation/duty/)由平台事件和巡查触发，使用单独配置的角色，并可在权限内无人确认地执行操作。

普通固定告警无需启用 AI。需要的只是接收运维通知时，可以先配置渠道与个人通知偏好。
