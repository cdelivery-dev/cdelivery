CDelivery 是自托管的應用程式維運平台。你提供伺服器和容器映像檔，通過控制台部署應用程式、設定存取入口、觀察執行狀態，並按需要接入自動檢查、定時任務和 AI 助手。

## 先理解四個對象

| 對象 | 含義 | 示例 |
| --- | --- | --- |
| 伺服器 | 提供計算資源及本地存儲的機器 | 一台 Linux 雲伺服器 |
| 分組 | 組織應用程式並提供組內通信網路 | `demo` |
| 應用程式 | 映像檔、設定和期望執行方式的組合 | `hello-web` |
| 副本 | 應用程式實際執行的實例 | 兩個相同的 Web 容器 |

分組便於組織和組內通信，不是按使用者隔離資料的權限邊界。Reader 可以讀取各分組的共享資訊；不要把將應用程式放入另一個分組當作保密措施。

## 從哪裡開始

1. 閱讀[安裝前準備](/docs/zh-tw/getting-started/requirements/)，確認系統、網路和存取方式。
2. 完成[安裝與首次設定](/docs/zh-tw/getting-started/installation/)，建立首個管理員。
3. 按[部署第一個應用程式](/docs/zh-tw/getting-started/first-app/)執行 Nginx，驗證完整部署連線路徑。
4. 閱讀[控制台導覽](/docs/zh-tw/getting-started/console/)，找到設定、日誌和平台管理入口。

首次使用只需完成安裝與一個應用程式部署。網域、HTTPS、Insight、消息渠道和 AI 模型按實際需要設定。

## 執行應用程式與維護平台

日常應用程式操作包括更換映像檔、調整資源、擴縮容、查看日誌、設定 XHealth 和 XJob。伺服器加入、分組管理、帳戶管理及平台組件設定則屬於管理員職責。

| 角色 | 主要權限 |
| --- | --- |
| Reader | 讀取共享資訊，管理自己的帳戶與 API 金鑰 |
| Operator | 另可執行應用程式、XHealth、XJob 和 Guardian 的維運操作 |
| Admin | 另可管理伺服器、分組、使用者及平台設定 |

詳細邊界見[角色與權限](/docs/zh-tw/administration/accounts/roles/)。API 金鑰還具有角色上限；AI 對話沿用綁定使用者的權限，自動值班使用單獨設定的角色。

## 如何判斷應用程式可用

部署提交成功只表示設定已被接受。還需要確認副本執行、應用程式監聽連接埠正確，並從預期的用戶端存取業務入口。執行狀態、XHealth 檢查結果和公網存取結果分別反映不同環節。

應用程式需要儲存資料時，在建立前閱讀[資料持久化](/docs/zh-tw/guides/apps/persistence/)。容器內未掛載的資料不會因為平台能夠重啟應用程式就自動獲得持久化保障。
