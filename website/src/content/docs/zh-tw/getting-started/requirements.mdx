安裝前先確定伺服器用途和控制台存取方式。單台機器即可開始；多台機器需要能夠通過穩定地址相互通信。

## 伺服器通信地址

伺服器間使用的地址必須能被其他伺服器存取。雲伺服器通常選擇內網地址；瀏覽器存取控制台的地址可以不同，例如公網地址或 SSH 隧道的本地地址。

`127.0.0.1` 只適合本機存取場景。準備加入更多伺服器時，不能把回環地址作為它們存取當前伺服器的地址。安裝器的 `--advertise-addr` 用於明確指定通信地址，重跑已有安裝不會自動遷移該地址。

## 網路與存取

| 連接埠 | 用途 | 放行範圍 |
| --- | --- | --- |
| TCP 9000 | 控制台及 API | 你的管理網路或 SSH 隧道 |
| TCP 80、443 | Pingress 的 HTTP/HTTPS 入口 | 需要存取應用程式的用戶端 |
| 應用程式發佈連接埠 | 直接存取應用程式，例如 TCP 8080 | 業務需要的用戶端 |
| TCP 2377 | 伺服器管理通信 | 參與部署的伺服器之間 |
| TCP/UDP 7946 | 伺服器發現與通信 | 參與部署的伺服器之間 |
| UDP 4789 | 應用程式跨伺服器通信 | 參與部署的伺服器之間 |

同時檢查雲安全組和宿主機防火牆。伺服器間連接埠不應對整個互聯網開放。連接埠用途可參考 [Docker 網路要求](https://docs.docker.com/engine/network/drivers/overlay/#requirements)。

本地管理遠程伺服器時，可以使用：

```sh
ssh -L 9000:127.0.0.1:9000 your-user@server.example.com
```

保持 SSH 會話打開，然後存取 `http://localhost:9000`。首次應用程式教程使用的 8080 連接埠需要另行轉發。

## 資料規劃

資料庫等有狀態應用程式使用指定伺服器上的本地資料卷。先選擇存儲伺服器和備份方式，再建立應用程式。平台中的副本、回復和重新部署不等同於資料庫備份。

網域不是完成首次部署的前提。之後設定 HTTPS 時，準備網域管理權限，並讓 DNS 指向執行 Pingress 的可達地址。

如果需要 IPv6，先檢查宿主機地址、路由和防火牆，再閱讀[網路常見問題](/docs/zh-tw/guides/networking/faq/)。安裝器的網路準備不能替代外部連通性驗證。

完成這些檢查後，繼續[安裝部署](/docs/zh-tw/getting-started/installation/)。
