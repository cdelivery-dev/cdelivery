Operator 和 Admin 可以送出應用程式更新或 PostgreSQL 變更，並處理未完成的發布。CDelivery 透過 [XHealth](/docs/zh-tw/guides/release-safety/xhealth/) 在預覽執行個體上執行發布檢查。

## 選擇檢查並提交

設定與範例請見[應用程式依賴](/docs/zh-tw/guides/apps/dependencies/app/)及 [PostgreSQL 資料庫依賴](/docs/zh-tw/guides/apps/dependencies/postgresql/)。

儲存應用程式部署設定即可提交更新。映像檔、環境變數、掛載、XConfig、資源、排程、網路、分組、憑證、日誌、重新啟動策略和更新策略等變化都可能觸發檢查；只改描述或副本數量不會觸發。

**如果沒有應用程式參與檢查，更新會直接上線，SQL 會直接在正式資料庫執行。**

## 測試與上線

CDelivery 會準備預覽執行個體。如果是資料庫變更，會先在測試資料庫執行 SQL，再執行所選的檢查。全部通過後，平台會清理測試資源，然後套用正式環境的設定，或在正式資料庫執行同一段 SQL。測試時寫入測試資料庫的資料會一併清除。

預覽執行個體透過預覽連線存取這次變更的目標，其他依賴則沿用原本的連線。請為同時執行的正式應用程式與預覽執行個體預留資源。

## 處理停止的變更

檢查失敗或執行中斷時，平台會保留變更紀錄、診斷資訊和剩餘的暫存資源。正式環境的變更需要手動重試。可在應用程式的**總覽 → 目前修改**或對應的依賴頁查看詳細資料，並查閱**預覽應用程式**和**發布檢查**的[日誌](/docs/zh-tw/guides/observability/logs/application/)。

可用的操作取決於變更停在哪個階段。

| 操作 | 結果 |
| --- | --- |
| 略過檢查並上線 | 清理測試資源，不再完成檢查，直接套用正式變更 |
| 再次執行 | 在正式環境重新執行變更。資料庫變更會重新執行原始 SQL，請先確認上一次的執行結果 |
| 確認完成 | 確認正式環境結果並完成清理，不執行 SQL，也不再次套用變更 |
| 取消 | 清理暫存資源並關閉變更，已經執行的正式變更會保留 |

在正式環境執行前，可以選擇略過檢查或取消變更。如果只剩清理工作，請選擇**確認完成**。若要重新測試，請先取消目前的變更，再重新送出。

## 完成與驗證

未完成變更會占用所有參與應用程式，包括其他分組中的依賴方。這些應用程式的設定更新、重新啟動、回復、刪除和 XHealth 修改會被阻止，自動擴縮容也會等待。先處理目前變更，再提交衝突操作或手動刪除其預覽資料卷。

每個目標只保留最新一條變更。完成後檢查線上副本和真實業務請求。[應用程式回復](/docs/zh-tw/guides/release-safety/rollback/)還原設定，不撤銷 SQL，也不還原資料庫內容。
