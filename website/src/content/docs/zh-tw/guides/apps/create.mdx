建立應用程式需要 Operator 或 Admin，並且目標分組已經存在。先準備映像檔、容器連接埠和必需設定；需要持久化資料時，還應由管理員準備目標伺服器的資料卷。

## 從空白設定開始

1. 在側欄找到目標分組，點擊建立應用程式。
2. 填寫唯一的應用程式名稱和可選描述。名稱在整個平台中唯一，不能只依賴分組區分重名應用程式。
3. 填寫映像檔；私有映像檔在映像檔設定中填寫使用者名和密碼或權杖。
4. 按映像檔要求設定啟動指令、環境變數、連接埠和檔案。
5. 設定副本、資源和調度條件；簡單無狀態應用程式可先使用預設值。
6. 檢查全部設定後建立，等待應用程式概覽顯示執行結果。

名稱為 1–16 個小寫字母、數字或連字符，首尾不能是連字符；平台保留名稱不能使用。描述最多 500 個字符。控制台不提供建立後的應用程式改名操作。

## 建立時應明確的設定

| 設定 | 說明 |
| --- | --- |
| 映像檔 | 使用儲存庫實際存在的映像檔與標籤 |
| 啟動指令 | 留空使用映像檔預設值；自訂指令需要包含可執行程序 |
| 環境變數 | 按映像檔文件填寫，值不自動進行 shell 展開 |
| 發佈連接埠 | 容器內連接埠與用戶端存取連接埠分別填寫 |
| 檔案與存儲 | 選擇設定檔案或本地資料方式，提前確認有狀態限制 |
| 資源與副本 | 按單個副本計算資源，確認伺服器有足夠容量 |

首次練習可使用[完整 Nginx 示例](/docs/zh-tw/getting-started/first-app/)。

## 使用資料庫模板

建立頁面提供 PostgreSQL、MySQL 和 MariaDB 模板。模板會預填映像檔、連接埠、環境變數和生成的密碼，但仍需你選擇目標伺服器與資料卷。

1. 選擇資料庫模板，確認映像檔版本和生成的環境變數。
2. 儲存生成的密碼到你自己的憑據管理工具。
3. 選擇已準備的資料卷及模板對應的資料目錄。
4. 如果資料庫只供同分組應用程式存取，移除不必要的對外發佈連接埠。
5. 建立後檢查資料庫初始化日誌，再使用用戶端驗證連接。

模板是部署設定的起點。已有資料的格式兼容、資料庫升級和備份仍需遵循資料庫自身的規則，詳見[有狀態應用程式](/docs/zh-tw/guides/apps/persistence/stateful/)。

## 驗證與失敗處理

副本進入執行狀態後，檢查業務回應或資料庫連接。映像檔下載失敗時先核對儲存庫與憑據；等待調度時檢查資源、標籤及目標伺服器；進程反復退出時檢查日誌、指令、環境變數和掛載路徑。

建立請求超時或回傳錯誤後，先回到應用程式清單確認資源是否已經出現，再決定是否重試。不要通過連續建立相同名稱來判斷操作是否成功。
