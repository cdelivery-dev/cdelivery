副本設定決定應用程式需要執行多少個實例。修改需要 Operator 或 Admin。本地資料應用程式固定一個副本，不使用動態擴縮容。

## 固定副本

在應用程式設定中選擇固定模式，填寫期望數量並儲存。副本數允許 1–65,536；實際能夠執行多少仍受伺服器資源及調度條件限制。

增加副本前確認應用程式支援並行執行：進程內會話、本地臨時檔案或重複消費任務，都可能需要應用程式自身處理。副本數不是資料庫複製設定。

## 自動擴縮容

選擇動態模式，設定最小和最大副本數。最小值至少為 1，最大值不能小於最小值。未填寫最大值也不表示可以突破平台上限、資源或調度約束。

自動判斷依賴有效的 CPU 採樣。先在 [Insight 設定](/docs/zh-tw/guides/observability/settings/)中確認採集組件工作，並檢查現有副本都已執行。

| 當前行為 | 說明 |
| --- | --- |
| 評估週期 | 通常每 30 秒檢查 |
| 採樣窗口 | 至少 60 秒，並隨採樣間隔調整 |
| 擴容方向 | CPU 利用率超過 70% 時評估擴容 |
| 目標利用率 | 按約 60% 計算所需副本 |
| 縮容方向 | 低於 50% 持續至少 5 分鐘後評估 |
| 資料不足 | 保持當前數量，等待有效樣本 |

這些條件共同決定調整，並不保證到達某個時間點就立即增加或減少副本。部署、設定變化、樣本不完整和容量不足都可能使控制器等待。

## CPU 限制的影響

設定 CPU 限制時，應用程式負載按該限制解釋。未設定限制時，計算會考慮伺服器 CPU 核數，擴容容量判斷也更保守，不應期待在同一台伺服器上持續增加未設 CPU 限制的副本。

希望在同一伺服器執行多個自動擴容副本時，應設定合理的 [CPU 限制](/docs/zh-tw/guides/apps/resources/)，同時確認每台伺服器的副本上限允許這種分布。

## 驗證和排障

1. 儲存動態範圍，等待初始副本穩定執行。
2. 檢查指標是否持續更新，所有執行副本是否都有有效採樣。
3. 在可控測試負載下觀察期望副本和實際副本。
4. 對照調度標籤、資源預留和每伺服器上限檢查可用容量。

負載較高卻未擴容時，依次檢查採樣、正在進行的更新、當前最大值和伺服器容量。負載降低後未立即縮容通常需要等待持續低負載窗口；頻繁改設定會影響觀察窗口。

切回固定模式後，由你明確指定副本數。更改策略後仍應觀察業務錯誤率和延遲，不能只根據副本數量判斷效果。
