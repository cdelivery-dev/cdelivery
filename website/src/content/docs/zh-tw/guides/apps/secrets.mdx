機密資料用來保存應用程式需要的密碼、權杖和憑證檔案。建立一次後，即可在不同分組的應用程式中重複使用。

| 類型 | 使用方式 |
| --- | --- |
| 文字 | 以環境變數提供給應用程式，例如 API 權杖。 |
| 檔案 | 透過 XConfig 掛載為唯讀檔案，例如憑證設定檔。 |

## 建立機密資料

建立、使用和刪除機密資料需要 Operator 或 Admin；Reader 可以查看名稱、類型和說明。

<Steps>

1. 開啟側欄的**機密資料**頁面，點擊**建立**。
2. 選擇**文字**或**檔案**，填寫名稱及選填的說明。
3. 輸入文字內容，或選擇要上傳的本機檔案。
4. 點擊**建立**，確認新機密資料出現在清單中。

</Steps>

內容不可為空，大小須小於 500 KiB；說明最多 64 字。文字支援多行，並保留空白及末尾換行。

建立後無法在平台查看、下載或修改內容。需要更換內容時，建立新的機密資料，再更新應用程式的選擇。

名稱和說明對有讀取權限的帳戶可見；應用程式若將機密資料內容寫入日誌，日誌中仍會出現這些內容。

## 在應用程式中使用

### 用作環境變數

<Steps>

1. 開啟應用程式建立頁或設定頁，在環境變數中新增一項。
2. 填寫變數名稱，例如 `API_TOKEN`，將來源切換為**機密資料**。
3. 選擇已建立的文字機密資料，例如 `api-token`，確認該項。
4. 儲存整份應用程式設定，等待部署完成，再確認應用程式能正常存取對應服務。

</Steps>

### 掛載為檔案

<Steps>

1. 在應用程式的檔案與儲存設定中新增設定檔。
2. 填寫容器內檔案路徑，例如 `/etc/app/credentials.json`。
3. 將來源切換為**機密資料**，選擇已建立的檔案機密資料並確認。
4. 儲存應用程式設定，等待部署完成，再確認應用程式能讀取該路徑。

</Steps>

檔案以唯讀方式提供給應用程式，使用本機資料卷的應用程式也能使用。較大的設定內容適合使用檔案機密資料。

## 更換與刪除

<Steps>

1. 使用新名稱建立替代內容，例如 `api-token-v2`。
2. 編輯需要更換的應用程式，將原本的選擇改為新機密資料並儲存。
3. 確認新部署運作正常後，回到機密資料清單刪除不再使用的舊機密資料。

</Steps>

目前的應用程式、執行中的任務或可回復設定仍使用舊機密資料時，刪除會被拒絕。確認這些使用關係已結束後再刪除。
