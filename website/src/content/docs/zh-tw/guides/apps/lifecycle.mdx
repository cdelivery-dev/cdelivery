更新和重啟需要 Operator 或 Admin。執行前先檢查應用程式狀態及是否有正在進行的 Guardian 驗證，避免把多次操作疊加在未完成的發佈上。

## 選擇合適操作

| 目標 | 使用方式 |
| --- | --- |
| 修改映像檔、環境變數或其他設定 | 編輯設定並儲存 |
| 使用當前設定重新建立執行容器 | 重啟 |
| 撤銷可用的上一份部署設定或候選發佈 | [回復與失敗處理](/docs/zh-tw/guides/release-safety/rollback/) |
| 徹底移除應用程式 | [刪除應用程式](/docs/zh-tw/guides/apps/delete/) |

重複儲存未變化的設定不會強制更新容器。同名映像檔標籤在儲存庫中發生變化，也不會自動觸發發佈；業務版本更新應使用可識別的新標籤。

## 更新設定

1. 記錄當前映像檔版本及關鍵設定。
2. 編輯需要改變的字段，保留不需要改變的設定。
3. 核對更新順序、並行度及容量。
4. 儲存後查看應用程式概覽與事件。
5. 等待實際副本穩定，再檢查日誌、XHealth 和業務入口。

映像檔、容器參數、設定檔案等相關變化在啟用 Guardian 時可能進入候選驗證流程。並不是所有字段修改都會建立候選發佈，具體見[發佈驗證](/docs/zh-tw/guides/release-safety/)。

## 重啟應用程式

重啟會要求執行容器按當前設定重新建立，並使用應用程式更新策略。它不是單純向原進程發送一個信號，也不修改資料庫已經寫入的資料。

預設更新策略會並行處理全部副本，並先停止舊副本。需要保持連續存取時，先評估[更新策略](/docs/zh-tw/guides/release-safety/update-strategy/)、額外容量及應用程式是否允許並行執行。

單副本應用程式重啟可能中斷連接。本地資料應用程式應先檢查備份和資料庫停止要求。

## 操作完成的判斷

儲存或重啟請求成功後，還需確認：

- 實際副本數量符合期望。
- 沒有持續等待、失敗或重啟的容器。
- 新容器日誌沒有啟動錯誤。
- 業務請求和相關健康檢查正常。
- 如果使用 Guardian，候選驗證與推廣已完成。

發生錯誤時，先判斷操作是否已部分生效，再決定重試、修正設定或回復。連續點擊重啟會增加判斷執行狀態的難度。

## 回復的邊界

回復依賴當前可用的上一份設定，不提供任意歷史版本選擇。它不能撤銷資料庫遷移、外部服務呼叫或已寫入的資料。

還應注意回復執行策略與正向更新並非完全相同：當前回復並行處理全部副本，失敗動作是繼續。完整說明見[回復與失敗處理](/docs/zh-tw/guides/release-safety/rollback/)。
