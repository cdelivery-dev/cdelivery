設定檔案通過目標路徑進入容器。上傳新內容會形成新的部署設定，不能把它視為直接修改正在執行的容器檔案。

以下範例使用一般 XConfig 檔案上傳。更換[檔案機密資料](/docs/zh-tw/guides/apps/secrets/)時，先建立新機密資料，再編輯既有掛載項選擇它並儲存應用程式設定。

## 準備一個首頁檔案

將以下內容儲存為 `index.html`，用於 Hello 入門應用程式（`ghcr.io/cdelivery-dev/hello:1.0.0`），目標路徑為 `/www/index.html`：

```html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>CDelivery Hello</title></head>
<body><h1>Hello from XConfig</h1></body>
</html>
```

在本機儲存檔案後，透過[XConfig](/docs/zh-tw/guides/apps/xconfig/)上傳。保留預設啟動指令及 TCP 80 → 8080 連接埠映射。更新完成後存取 `/`，應看到 `Hello from XConfig`，取代預設的請求資訊。移除該掛載後，新容器恢復預設回應。

## 替換現有內容

<Steps>

1. 打開應用程式設定，在設定檔案清單編輯現有項。
2. 選擇新的本地檔案。當前介面在編輯已有項時固定目標路徑。
3. 確認對話框，然後儲存應用程式設定。
4. 查看更新或 Guardian 驗證狀態。
5. 請求應用程式入口，確認回應已經來自新設定。

</Steps>

改變目標路徑時，刪除舊行，再添加新路徑的檔案。儲存前確認清單仍包含需要保留的其他檔案。移除一行並儲存後，該檔案將不再出現在新的應用程式設定中。

## 更新如何生效

未啟用 Guardian 時，設定變化按應用程式更新策略部署；啟用且符合條件時，新設定先進入驗證流程。驗證失敗不能解釋為新內容已在正式實例生效。

設定更新可能替換容器，不能假設程序會收到某個自動“熱加載”信號。應用程式能否熱加載屬於應用程式自身行為。需要持續寫入的檔案也不應由 XConfig 承擔。

## 驗證掛載

| 檢查項 | 應確認的結果 |
| --- | --- |
| 目標路徑 | 與應用程式實際讀取位置一致 |
| 應用程式日誌 | 沒有語法錯誤、權限錯誤或檔案不存在 |
| 副本狀態 | 更新完成，未持續失敗或重新啟動 |
| 業務回應 | 新設定確實生效 |
| 健康檢查 | 使用相關路徑的檢查通過 |

僅改變本地源檔案不會自動更新已上傳的版本。每次發佈新內容都需要重新上傳並儲存。

## 失敗處理

語法錯誤時先修正源檔案再上傳。錯誤路徑時核對映像檔的設定佈局。Guardian 拒絕推廣時查看候選應用程式及檢查日誌，參見[發佈驗證](/docs/zh-tw/guides/release-safety/guardian/)。

需要回到舊設定時，使用實際可用的[回復方式](/docs/zh-tw/guides/release-safety/rollback/)或重新上傳儲存好的源檔案。不要依賴被移除的設定引用永遠保留。
