設定檔案通過目標路徑進入容器。上傳新內容會形成新的部署設定，不能把它視為直接修改正在執行的容器檔案。

## 準備一個完整設定

以下檔案可用於 Nginx 入門應用程式，目標路徑為 `/etc/nginx/conf.d/default.conf`：

```nginx
server {
    listen 80;
    location / {
        default_type text/plain;
        return 200 "Hello from CDelivery\n";
    }
}
```

在本地儲存檔案後，通過 [XConfig](/docs/zh-tw/guides/apps/xconfig/)上傳。映像檔需要包含 Nginx，並使用會加載該目錄的設定。可以保留入門教程的 TCP 80 → 8080 連接埠映射。

## 替換現有內容

1. 打開應用程式設定，在設定檔案清單編輯現有項。
2. 選擇新的本地檔案。當前界面在編輯已有項時固定目標路徑。
3. 確認對話框，然後儲存應用程式設定。
4. 查看更新或 Guardian 驗證狀態。
5. 請求應用程式入口，確認回應已經來自新設定。

改變目標路徑時，刪除舊行，再添加新路徑的檔案。儲存前確認清單仍包含需要保留的其他檔案。移除一行並儲存後，該檔案將不再出現在新的應用程式設定中。

## 更新如何生效

未啟用 Guardian 時，設定變化按應用程式更新策略部署；啟用且符合條件時，新設定先進入驗證流程。驗證失敗不能解釋為新內容已在正式實例生效。

設定更新可能替換容器，不能假設進程會收到某個自動“熱加載”信號。應用程式能否熱加載屬於應用程式自身行為。需要持續寫入的檔案也不應由 XConfig 承擔。

## 驗證掛載

| 檢查項 | 應確認的結果 |
| --- | --- |
| 目標路徑 | 與應用程式實際讀取位置一致 |
| 應用程式日誌 | 沒有語法錯誤、權限錯誤或檔案不存在 |
| 副本狀態 | 更新完成，未持續失敗或重啟 |
| 業務回應 | 新設定確實生效 |
| 健康檢查 | 使用相關路徑的檢查通過 |

僅改變本地源檔案不會自動更新已上傳的版本。每次發佈新內容都需要重新上傳並儲存。

## 失敗處理

語法錯誤時先修正源檔案再上傳。錯誤路徑時核對映像檔的設定佈局。Guardian 拒絕推廣時查看候選應用程式及檢查日誌，參見[發佈驗證](/docs/zh-tw/guides/release-safety/)。

需要回到舊設定時，使用實際可用的[回復方式](/docs/zh-tw/guides/release-safety/rollback/)或重新上傳儲存好的源檔案。不要依賴被移除的設定引用永遠保留。
