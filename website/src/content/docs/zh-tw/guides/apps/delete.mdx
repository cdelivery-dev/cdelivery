刪除應用程式需要 Operator 或 Admin。刪除會停止該應用程式提供的服務，適合永久下線或移除測試應用程式；需要暫時修復執行狀態時，先考慮設定調整或重啟。

## 刪除前檢查

1. 確認應用程式名稱、所屬分組及業務負責人。
2. 檢查是否仍有用戶端、其他應用程式或網域存取它。
3. 儲存需要保留的設定源檔案和版本資訊。
4. 對有狀態應用程式完成必要的資料備份。
5. 記錄卷所在伺服器、卷名稱和容器內路徑，便於之後識別保留資料。

如果需要保留任務或檢查設定，應在刪除前自行記錄。刪除不是導出或備份操作。

## 執行刪除

打開目標應用程式，使用刪除操作，並核對確認提示中的對象。提交後回到分組或應用程式清單，確認應用程式已移除，再檢查外部存取是否符合預期。

底層容器和其他資源的清理可能是異步完成的。請求超時或報錯時，先檢查應用程式是否仍存在，再決定是否重試。

## 哪些內容會變化

| 內容 | 刪除後的處理 |
| --- | --- |
| 應用程式及執行容器 | 移除應用程式，執行任務隨後停止和清理 |
| XHealth | 隨應用程式移除 |
| XJob | 隨應用程式移除，不能繼續執行該應用程式的任務 |
| Guardian | 相關候選驗證資源被清理 |
| 分組 | 保留，不隨單個應用程式刪除 |
| 本地資料卷 | 保留，需要管理員另行管理 |
| 外部 DNS | 不會替你修改網域服務商中的記錄 |

應用程式的網域路由隨應用程式設定失去作用，但 DNS 仍可能指向 Pingress。下線完成後檢查這些入口，避免遺留無效業務地址。

## 處理保留資料

在[資料卷管理](/docs/zh-tw/administration/nodes/volumes/)中確認資料所在伺服器、卷大小及使用情況。只有確定不再需要資料並滿足備份要求後，才刪除對應卷。

XConfig 不作為長期歸檔保留承諾。即使某些日誌、指標或事件仍在保留窗口內，也不能依賴刪除後的應用程式入口長期存取它們。

## 同名重建

重新建立同名應用程式會產生新的執行資源和身份。歷史日誌、指標和舊設定不應被視為自動接續到新應用程式。使用原卷重建時，還需核對資料格式、憑據和映像檔兼容性。

刪除後出現持續存取請求時，檢查 DNS、上游呼叫和監控設定，而不只是應用程式清單。
