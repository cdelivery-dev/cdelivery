映像檔決定應用程式執行的程序及預設啟動方式。先從映像檔發佈者的文件確認標籤、監聽連接埠、資料目錄和必需環境變數，再填寫應用程式設定。

## 映像檔名稱

| 示例 | 含義 |
| --- | --- |
| `nginx:stable-alpine` | 公開映像檔及標籤，適合入門演示 |
| `registry.example.com/team/api:1.2.3` | 指定私有儲存庫、路徑和版本 |
| `registry.example.com:5000/team/api:1.2.3` | 儲存庫使用非預設連接埠 |

不填寫 `https://` 前綴。儲存庫路徑使用符合界面校驗的名稱；當前輸入不接受 `@sha256:...` 摘要引用。部署重要業務時，優先使用能明確區分發佈版本的標籤。

平台不會持續輪詢儲存庫，自動把同名標籤的新映像檔發佈到應用程式。儲存庫中覆蓋舊標籤也不會自動改變已經執行的容器。

## 私有儲存庫認證

建立或編輯應用程式，打開映像檔設定，填寫儲存庫使用者名和密碼或存取權杖。優先使用只具有拉取權限的專用憑據。

平台不會在讀取應用程式資訊時回顯密碼。當前界面在使用者名非空時要求填寫密碼或權杖：如果只是查看已有認證，關閉編輯框即可；需要更換認證時，重新填寫使用者名和權杖並確認。

在未修改憑據且儲存庫作用域不變時，已有憑據可以保留。切換到不同儲存庫後不要假定舊憑據仍有效，應按新儲存庫重新設定。清除認證前先確認映像檔確實允許匿名拉取。

## 更新映像檔

1. 發佈並確認目標標籤存在。
2. 打開應用程式設定，修改映像檔標籤及相應參數。
3. 檢查[更新策略](/docs/zh-tw/guides/release-safety/update-strategy/)，確認副本和容量允許更新。
4. 儲存後查看副本、日誌及 XHealth 結果。
5. 啟用 Guardian 的應用程式，按[發佈驗證](/docs/zh-tw/guides/release-safety/)查看候選設定是否通過。

只儲存未變化的映像檔字符串不會強制重部署。需要重新建立容器時使用[更新與重啟](/docs/zh-tw/guides/apps/lifecycle/)中的重啟操作；要確保發佈版本可追蹤，仍應使用新的版本標籤。

## 拉取失敗排查

| 錯誤方向 | 檢查內容 |
| --- | --- |
| 未授權或拒絕存取 | 使用者名、權杖權限、儲存庫路徑及權杖是否過期 |
| 標籤不存在 | 儲存庫中的實際標籤、大小寫及映像檔推送是否完成 |
| 連接或憑證失敗 | 伺服器出站網路、DNS、儲存庫 TLS 設定 |
| 平台架構不匹配 | 映像檔是否提供目標伺服器 CPU 架構 |
| 只有部分伺服器失敗 | 分別檢查這些伺服器到儲存庫的連接和映像檔支援 |

不要把儲存庫密碼寫入映像檔名稱、環境變數示例或共享故障截圖。公開映像檔使用方式可參考 [Nginx 官方映像檔](https://hub.docker.com/_/nginx)。
