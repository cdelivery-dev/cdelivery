XJob 清單與詳情顯示當前或最近一次執行狀態，以及上次、下次執行時間。當前界面不是完整的歷史執行清單；需要較早的證據時，應在日誌和事件的保留範圍內查找。

API 欄位 `last_run` 是觀測到的最近任務建立時間，不是結束時間。任務記錄缺失不能證明成功。逾時停止會記錄 `XJobFailed` 事件；任務記錄已消失時，應結合事件與日誌排查。

## 解釋結果

| 狀態 | 說明 |
| --- | --- |
| 等待 | 尚未得到本輪完成結果 |
| 執行中 | 指令仍在執行 |
| 通過 | 指令成功退出 |
| 失敗 | 指令失敗，查看錯誤和日誌 |
| 已結束但無成功結論 | 不能視為業務執行成功，需要進一步檢查 |

結束代碼成功只說明指令按自身定義回傳成功。關鍵業務任務還應驗證實際輸出或資料變化，例如檔案確實生成、同步記錄確實出現。

## 查看日誌

1. 打開任務所屬應用程式的日誌頁面。
2. 選擇對應 XJob 任務來源。
3. 將時間範圍定位到任務開始和結束附近。
4. 根據錯誤資訊區分指令、依賴、網路及業務問題。

日誌可用性取決於應用程式日誌驅動、採集狀態及保留設定。沒有日誌不等於任務沒有執行，也不等於執行成功。

## 常見問題

| 現象 | 檢查內容 |
| --- | --- |
| 指令不存在 | 應用程式映像檔是否包含程序、腳本路徑及執行權限 |
| shell 表達式沒有生效 | 是否顯式使用 shell，變數和引號是否正確 |
| 連接服務失敗 | 同分組服務名稱、內部連接埠、憑據及服務狀態 |
| 下次執行時間不符 | 等待間隔、本輪結束時間及任務記錄是否缺失 |
| 手動執行按鈕不可用 | 當前是否仍有活動執行、是否具有操作權限 |
| 長時間不結束 | 指令是否會退出、外部請求是否掛起、任務是否適合獨立應用程式 |

執行逾時依設定生效，輪詢和停止過程可能造成延遲。任務應具有明確結束條件，避免用無限循環充當調度工作。

## 失敗後重試

先判斷任務是否已完成部分寫入，再決定是否手動重試。重新執行不會自動撤銷上一輪副作用；去重、斷點續作和資料一致性由實際業務指令負責。

保留任務名稱、時間、完整錯誤和必要日誌，分享前移除憑據。需要持續接收失敗資訊時，設定[通知渠道](/docs/zh-tw/guides/automation/im/notifications/)。
