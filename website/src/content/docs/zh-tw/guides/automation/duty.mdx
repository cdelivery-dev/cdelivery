自動值班會分析平台事件，並按設定間隔巡查健康、容量和趨勢。它使用單獨設定的角色，可在該權限範圍內無需人工確認地執行操作。

## 啟用步驟

1. 管理員先完成並驗證[模型設定](/docs/zh-tw/guides/automation/models/)。
2. 打開 **Agent → 值班**。
3. 選擇角色、回應策略、巡查間隔和通知語言。
4. 確認接收者已設定[通知渠道](/docs/zh-tw/guides/automation/im/notifications/)。
5. 啟用值班，觀察後續分析與事件記錄。

初始角色為 Reader，初始策略為接近臨界，初始巡查間隔為 30 分鐘。通知語言預設英文，需按接收者需要明確調整。

## 角色與自動操作

| 角色 | 對值班的影響 |
| --- | --- |
| Reader | 主要進行共享資訊查詢與分析 |
| Operator | 可執行應用程式、檢查、任務和發佈相關的允許操作 |
| Admin | 可執行更多平台管理操作 |

值班身份沒有某個個人帳戶的 Own 資源。角色越高，可執行的自動操作範圍越大，應按實際職責選擇。

普通使用者對話的權限仍來自綁定帳戶，不受值班角色直接替代。

## 回應策略

| 策略 | 使用含義 |
| --- | --- |
| EarlyRisk | 有足夠證據時回應早期風險 |
| NearCritical | 接近容量或健康臨界時重點處理 |
| LimitOrFailure | 主要在達到限制或確認故障時處理 |

策略控制分析、通知和行動時機，不是一組對所有業務都適用的固定 CPU 或內存閾值。

巡查間隔允許 15 分鐘至 24 小時。故障事件的 AI 分析不需要等到下一次巡查，因此把間隔調長不等於關閉事件回應。

## 通知接收

接收者需要啟用相應渠道通知，且帳戶角色應不低於本輪值班使用的角色。例如以 Admin 執行的值班通知不會按同樣方式發給只有 Reader 權限的帳戶。

AI 生成通知使用值班的通知語言；普通固定告警有獨立發送流程，不依賴模型或值班開關。

## 驗證與停用

啟用後檢查通知、查詢結果和操作事件，確認目標、權限與實際結果符合預期。模型結論可能需要人工復核，尤其當採集資料缺失或外部依賴資訊不足時。

停用值班會停止後續值班分析，但不會撤銷已經執行的操作，也不會自動關閉普通告警或使用者發起的 AI 對話。發現不符合預期的自動行為時，先停用並核對事件，再處理已發生的變更。
