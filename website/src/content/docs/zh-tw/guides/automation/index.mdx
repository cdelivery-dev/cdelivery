AI 助手結合平台操作、日誌、指標和事件回答維運問題。交互對話通過已設定的消息渠道進行；模型設定和渠道綁定是兩個獨立步驟。

## 開始對話

1. 管理員完成[模型設定](/docs/zh-tw/guides/automation/models/)。
2. 管理員接入一種[消息渠道](/docs/zh-tw/guides/automation/im/)。
3. 你在自己的帳戶中綁定該渠道的不可變使用者 ID。
4. 向 Bot 發送一條唯讀問題，例如“檢查 hello-web 當前副本和最近一次健康檢查結果”。
5. 核對回復中的對象、時間和實際查詢結果。

支援郵件接入時，管理員還需要設定接收郵件所需的 IMAP 及身份驗證條件。僅設定 SMTP 發送通知不足以開啟郵件對話。

## 提問方式

提供明確對象、時間和期望結果，可以減少無關查詢。例如：

- “查看 hello-web 最近 30 分鐘的錯誤日誌，並與最近一次更新對照。”
- “比較這台伺服器的內存壓力與上面的應用程式重啟時間。”
- “檢查資料庫連接失敗的應用程式設定，先給出原因和修改建議。”

當需要執行寫操作時，明確描述目標和範圍。完成後到控制台核對狀態及[操作事件](/docs/zh-tw/guides/observability/events/)，不要僅依據自然語言表述判斷操作成功。

## 權限如何生效

對話使用綁定使用者的實時權限。Reader 可以讀取共享資訊及管理自身資源；Operator 和 Admin 按各自角色執行更多操作。Bot 不會因為由管理員建立就讓所有對話使用者獲得管理員權限。

綁定的是平台回傳的不可變使用者 ID，而不是暱稱或群名稱。填寫他人的 ID 可能把你的權限和資料暴露給對應帳戶，必須自行核對，參見[消息與通知](/docs/zh-tw/guides/automation/im/)。

## 資料與判斷邊界

模型能夠分析的內容取決於權限、可用工具、採集狀態和保留時間。缺失指標或沒有日誌不能單獨證明系統正常；要求助手區分觀察到的事實、推測和未驗證部分。

設定外部模型服務時，相關問題及被查詢的上下文會用於模型請求。應按自己的資料要求選擇提供商與服務端點。

## 對話與自動值班

對話由使用者發起；[自動值班](/docs/zh-tw/guides/automation/duty/)由平台事件和巡查觸發，使用單獨設定的角色，並可在權限內無人確認地執行操作。

普通固定告警無需啟用 AI。需要的只是接收維運通知時，可以先設定渠道與個人通知偏好。
