通知能否到達取決於平台渠道、個人接收設定和通知對象。管理員儲存機器人憑證，不會自動替所有使用者綁定身份或開啟訂閱。

## 設定順序

1. Admin 在設定中啟用郵件或消息渠道。
2. 每位使用者在個人帳戶中填寫自己的消息平台 ID，或確認帳戶郵箱。
3. 開啟需要的郵件和消息通知；已綁定身份與已訂閱通知是兩件事。
4. 如果需要 AI 值班分析，再設定模型與[自動值班](/docs/zh-tw/guides/automation/duty/)。
5. 在實際維運事件發生後核對事件、通知內容和接收對象。

不同消息平台的 ID 格式不同，參閱對應[渠道說明](/docs/zh-tw/guides/automation/im/)。顯示名、群 ID 和機器人 ID 不能通用。

## 誰會收到通知

普通維運告警會發送給符合接收條件且開啟通知的使用者。AI 值班通知還按值班角色篩選：接收人的角色必須不低於值班角色。例如，Operator 值班產生的通知發給訂閱的 Operator 和 Admin，Reader 不會收到這類通知。

值班通知使用值班設定中的通知語言；使用者發起的 AI 對話跟隨對話語言。停止自動值班不等於關閉所有普通維運告警。關閉個人通知也不等於刪除消息平台綁定。

## 按連線路徑排查

| 步驟 | 檢查內容 |
| --- | --- |
| 事件是否產生 | 應用程式狀態、檢查結果與操作事件，不能僅憑沒有通知判斷系統正常 |
| 渠道是否可用 | 平台憑證、應用程式發佈狀態、發送權限、出站網路 |
| 接收人是否正確 | 當前帳戶的郵箱或不可變使用者 ID |
| 是否訂閱 | 個人郵件開關及各消息渠道開關 |
| 角色是否符合 | 當前使用者角色與 AI 值班角色 |
| 平台是否接收 | 垃圾郵件、私聊限制、機器人存取範圍、限流 |
| AI 是否執行 | 模型和自動值班設定、分析期間的錯誤 |

排查時記錄發生時間、渠道、帳戶和相關事件。不要把機器人 Token、郵件密碼或 API 金鑰放入反饋內容。修改個人綁定後，先使用唯讀對話確認對應帳戶；不要依賴收到頭像或顯示名來判斷權限綁定正確。
