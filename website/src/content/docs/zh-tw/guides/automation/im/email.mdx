郵件通知只需要 SMTP。要通過郵件與 AI 對話，還需設定 IMAP 和[模型](/docs/zh-tw/guides/automation/models/)。請為平台準備一個專用郵箱，並確認伺服器能存取郵件服務商。

## 設定發送

1. 以 Admin 打開設定中的郵件渠道，填寫平台郵箱地址。
2. 填寫 SMTP 主機、連接埠和密碼。郵箱地址同時作為登入使用者名。
3. 連接埠 465 使用隱式 TLS；其他連接埠走服務端支援的加密升級連接。使用服務商明確支援的連接埠。
4. 儲存後，在個人帳戶中啟用郵件通知，檢查帳戶郵箱是否正確。

部分服務商要求應用程式專用密碼。例如 Google 的應用程式密碼需要帳戶啟用兩步驟驗證，且可能受組織策略限制，參閱[官方說明](https://support.google.com/accounts/answer/185833)。不能用一個不允許 SMTP 登入的普通密碼代替。

## 設定接收

| 字段 | 填寫方式 |
| --- | --- |
| IMAP 主機 | 服務商提供的收件伺服器 |
| 連接埠 | 預設 993，使用隱式 TLS |
| 密碼 | 對應平台郵箱的 IMAP 登入憑證 |
| authserv_id | 可信收件伺服器寫入 Authentication-Results 的認證伺服器標識 |

CDelivery 讀取 INBOX。首次連接或重建接收游標時從當前郵箱末尾開始，不會把歷史郵件重新當作操作請求。設定完成後發送一封新郵件驗證。

入站郵件的發件地址必須匹配現有 CDelivery 使用者；可信認證結果還必須同時通過 DKIM 和 DMARC。只看到 From 地址正確並不足以通過驗證。請從可信收件伺服器實際寫入的郵件頭確定 authserv_id，不能隨意填寫發件人的網域。

## 驗證與排障

用自己的帳戶郵箱發送一封新的純文字郵件，詢問應用程式狀態。確認郵箱收到回復，且回復對應當前帳戶的權限。

| 現象 | 檢查 |
| --- | --- |
| 儲存失敗 | SMTP/IMAP 地址、TLS、連接埠、登入憑證及出站網路 |
| 可以通知但不能對話 | IMAP、模型、發件地址、可信認證結果 |
| 新郵件不處理 | 是否進入 INBOX、是否在接收器啟動之後收到 |
| 通知未收到 | 個人通知開關、垃圾郵件、服務商投遞限制 |
| 換郵箱後認證失敗 | 更新對應 SMTP 和 IMAP 密碼，不能沿用舊地址的憑證 |

平台儲存憑證後不會回顯密碼。地址、主機或連接埠變化時重新提供相應憑證。通知對象和角色規則見[通知設定與排障](/docs/zh-tw/guides/automation/im/notifications/)。
