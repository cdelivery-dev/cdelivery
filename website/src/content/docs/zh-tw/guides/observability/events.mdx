事件記錄平台觀察到的操作和狀態變化，幫助定位問題發生前的變更。

## 查看事件

打開應用程式的事件頁面，選擇問題發生前後的時間範圍。查看事件時間、類型、對象、操作者以及詳細資訊，並與同一窗口的日誌和指標對照。

例如新版本發佈後出現失敗，應先找到設定變更時間，再檢查候選驗證、正式副本替換及錯誤日誌的先後順序。

## 事件與診斷狀態

| 資訊 | 應如何理解 |
| --- | --- |
| 設定或生命週期事件 | 說明平台記錄了某次操作或變化 |
| 執行異常 | 需要再查詢當前副本和更新狀態 |
| XHealth 失敗 | 需要查看最近一輪檢查的實際結果 |
| 恢復相關資訊 | 應結合當前業務回應確認恢復 |
| 當前沒有記錄 | 檢查時間範圍、收集狀態和保留期限 |

部分即時診斷記錄保存在記憶體中，重新啟動後可能消失。歷史事件保存在 Insight 中，可見範圍受收集狀態和保留期限影響。

## 定位操作者

事件中的來源有助於區分控制台、API 金鑰、AI 對話或自動值班等觸發方式。

AI 值班可能在設定的角色權限內執行操作。需要檢查它的行為邊界時，參見[自動值班](/docs/zh-tw/guides/automation/duty/)及[角色與權限](/docs/zh-tw/administration/accounts/roles/)。

## 建立排障時間線

<Steps>

1. 記錄使用者首次報告問題的時間。
2. 查看此前的發佈、重新啟動、擴縮容和設定事件。
3. 核對相關應用程式及伺服器的指標變化。
4. 查看同時間的業務、檢查和存取日誌。
5. 記錄已經驗證的恢復結果。

</Steps>

## 保留與分享

歷史事件的可見範圍受 Insight 儲存與保留設定影響。重要問題處理完成後，可在你自己的事故記錄中儲存必要時間線和證據。

分享時保留事件類型、時間和必要錯誤，同時移除驗證資訊和使用者敏感資訊。
