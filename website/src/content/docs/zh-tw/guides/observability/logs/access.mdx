存取日誌記錄經過 Pingress 的請求，幫助區分入口、路由和應用程式回應問題。直接存取應用程式發佈連接埠的請求不經過 Pingress，因此不應期待在這裡看到它。

## 查看存取記錄

應用程式設定網域後，可在應用程式日誌頁選擇存取日誌來源。先選時間範圍，再用界面提供的篩選條件縮小問題請求。

記錄清單展示請求時間、方法、路徑、狀態、耗時和用戶端地址。展開一條記錄可以查看更詳細的資訊。

| 字段 | 用途 |
| --- | --- |
| 網域與路徑 | 確認請求存取的入口 |
| 狀態及結果 | 區分實際 HTTP 回應與入口處理結果 |
| 目標連接埠與服務 | 核對匹配到的應用程式目標 |
| 節點 | 找到處理該請求的 Pingress 實例 |
| 請求和回應位元組數 | 瞭解流量大小 |
| 上游首位元組時間 | 觀察等待上游開始回應的時間 |
| 錯誤 | 定位連接或代理處理失敗 |

某些失敗發生在完整請求資訊可用之前，因此部分字段可能為空。

## 常見分析方式

**請求沒有記錄**：先檢查 DNS 是否指向這個入口、用戶端是否繞過 Pingress，以及採集和存儲是否正常。

**請求未命中預期應用程式**：核對網域、路徑前綴、請求頭和 Cookie 條件。應用程式範圍查詢只展示歸屬於該應用程式的記錄，未匹配請求需在相應入口範圍繼續排查。

**上游失敗**：檢查目標連接埠、容器監聽地址、實際副本和應用程式日誌。入口能夠收到請求不代表上游已經可用。

**請求較慢**：結合整體耗時、上游首位元組時間和應用程式指標分析，不能僅憑一條慢請求判斷伺服器資源不足。

## 用戶端地址

Pingress 記錄直接連接方的地址，並據此設定轉發請求頭。存在 CDN、其他代理或網路地址轉換時，記錄的地址可能不是最終使用者原始地址。

IPv6 網橋及真實用戶端地址相關檢查見[網路常見問題](/docs/zh-tw/guides/networking/faq/)。應用程式自身連接的對端通常是 Pingress，應區分連接地址和轉發請求頭。

## 資料限制

存取記錄依賴 Pingress 產生資料及 Insight 的可用性和保留設定。日誌遲到、保留到期和查詢失敗需要分別識別。

路徑和查詢資訊可能包含業務標識或其他敏感內容。對外分享記錄前檢查並脫敏，不要把請求日誌當成可以公開傳播的資料。
