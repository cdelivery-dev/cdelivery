應用程式指標用於觀察資源消耗和請求表現。打開應用程式的指標頁面，選擇覆蓋問題時間的範圍，再結合當前副本和發佈事件分析。

## 資源指標

| 類別 | 重點關注 |
| --- | --- |
| CPU | 使用量、限制、節流及壓力 |
| 內存 | 當前使用、工作集、限制、交換及內存不足相關指標 |
| 磁盤 I/O | 讀寫速率、操作次數及 I/O 壓力 |
| 網路 | 接收、發送速率及 TCP 重傳 |
| 進程 | 進程數量和限制 |
| 副本 | 期望與實際執行情況 |

圖表可用字段取決於採集環境。未提供或無法計算的值不能直接按零解釋。

## 請求指標

經過 Pingress 的請求可以提供請求率、錯誤比例、總耗時和上游首位元組時間等資訊。沒有經過 Pingress 的流量，不會自動出現在這組請求指標中。

延遲百分位表示選定窗口內的分布特徵。高百分位升高時，應結合請求量、錯誤狀態和應用程式日誌判斷，而不是只看平均值。

## 單位與聚合

CPU 使用量可能以核數或百分比展示，內存以位元組量或比例展示。閱讀時先看圖表單位、對象範圍和對應限制，不能把多核伺服器上的數值直接當作單核百分比。

擴大時間範圍後，圖表會使用更寬的時間桶。最小、平均、最大值與百分位具有不同含義；縮小窗口有助於觀察短暫峰值。

指標查詢時間跨度最長為 31 天，實際可用歷史還取決於保留期限。選擇更久以前的時間，不會恢復已被清理的資料。

## 一個排查示例

應用程式回應變慢時：

1. 找到延遲開始變化的時間。
2. 對照發佈、擴縮容和設定事件。
3. 查看 CPU 節流、內存壓力及 I/O 指標。
4. 查看同一時間的存取日誌和應用程式錯誤。
5. 核對是否所有副本都受到影響，以及它們所在伺服器是否異常。

CPU 較高可能是原因，也可能是業務負載增加的結果。單個相關指標不能獨立證明因果關係。

## 資料缺失

先確認 [Insight 與採集設定](/docs/zh-tw/guides/observability/settings/)、實際副本和時間範圍。剛建立或重啟的實例需要積累有效樣本；發生採集間斷時應保留缺失含義。

決定修改[資源限制](/docs/zh-tw/guides/apps/resources/)或[自動擴縮容](/docs/zh-tw/guides/apps/scaling/)前，至少觀察正常負載和代表性峰值。
