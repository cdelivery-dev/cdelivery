從伺服器清單打開目標伺服器，進入指標頁面。伺服器指標用於判斷整台機器的資源情況，與單個應用程式容器的指標範圍不同。

## 主要指標

| 類別 | 用途 |
| --- | --- |
| CPU | 查看總利用率、使用者態、內核態、I/O 等待和被佔用時間 |
| 內存與交換 | 判斷可用容量、壓力及交換使用 |
| 網路 | 查看物理網卡的收發速率 |
| 檔案系統 | 查看容量、使用比例和 inode 使用情況 |
| 壓力指標 | 判斷 CPU、內存或 I/O 等待對任務的影響 |
| 執行時間 | 輔助識別伺服器重啟或採樣連續性變化 |

檔案系統指標針對被採集的本地可寫塊設備檔案系統。不要假設清單覆蓋每個容器掛載、遠程檔案系統或所有臨時目錄。

## 時間與單位

普通伺服器採樣預設每 5 秒進行，檔案系統採樣每 5 分鐘進行。檔案系統圖表不會因為你將普通採樣間隔改為 1 秒就獲得秒級磁盤容量資料。

CPU 核數、百分比、內存位元組量、網路位元組每秒和執行時間各有不同單位。擴大查詢時間範圍會改變聚合粒度；缺失時間桶不代表資源用量為零。

## 判斷容量問題

1. 對照伺服器上的應用程式副本和資源預留。
2. 檢查問題時間段的 CPU、內存及檔案系統變化。
3. 查看是否同時出現應用程式重啟、調度等待或日誌寫入失敗。
4. 檢查 inode 和容量兩個維度，避免磁盤有剩餘空間卻無法建立檔案。
5. 在採取清理或遷移措施前確認資料所屬資源。

容器資源預留影響調度，伺服器實際用量反映執行情況，兩者不能互相替代。調整應用程式設定前參見[資源限制](/docs/zh-tw/guides/apps/resources/)。

## 採集異常

頁面沒有指標時，先檢查 Insight Agent、伺服器狀態及最近上報時間。伺服器剛加入、剛重啟、採集服務尚未執行或存儲暫時不可用，都可能造成缺失。

採集靜默是診斷線索，不是伺服器已經宕機的充分證據。應結合伺服器連接、任務狀態及平台錯誤進一步確認。

## 與管理操作配合

需要修改標籤時進入[伺服器標籤](/docs/zh-tw/administration/nodes/labels/)；需要查看或清理應用程式資料卷時進入[資料卷管理](/docs/zh-tw/administration/nodes/volumes/)。

不要僅根據一張容量圖表刪除未知資料目錄。平台資料、應用程式卷、映像檔和日誌可能具有不同的保留與恢復要求。
