Insight 負責觀測資料的存儲與查詢，採集組件提供伺服器及容器資料。設定需要 Admin，入口位於控制台的 Insight 頁面。

## 首次啟用

1. 選擇可用的服務端與採集端版本。
2. 選擇存儲類型，並填寫對應位置與憑據。
3. 設定服務端部署位置。
4. 設定保留天數、採樣間隔及緩衝資料落盤間隔。
5. 儲存後檢查服務端和採集端的實際執行狀態。
6. 打開伺服器及應用程式指標，驗證資料開始出現。

## 存儲選項

| 類型 | 需要準備 |
| --- | --- |
| 本地 | 可持久執行的目標伺服器及本地存儲容量 |
| S3 | 區域、存儲桶、存取金鑰和秘密金鑰 |
| S3 兼容 | 額外填寫服務端點，並使用該服務要求的區域 |
| GCS | 存儲桶與服務帳戶憑據 JSON |
| Azure | 容器名稱、帳戶名稱和帳戶金鑰 |

按存儲服務要求授予讀寫所需權限，並保管憑據。首次啟用後，存儲位置和類型受到限制，主要允許更新區域及認證資訊；本地存儲的部署位置也固定。不要把編輯表單當作自動資料遷移功能。

## 時間設定

| 設定 | 界面初始值 | 範圍或含義 |
| --- | --- | --- |
| 保留期限 | 30 天 | 1–3650 天 |
| 採樣間隔 | 5 秒 | 1–60 秒 |
| 落盤間隔 | 3 分鐘 | 控制緩衝資料寫入存儲的時間，按界面單位填寫 |
| 檔案系統採樣 | 5 分鐘 | 獨立於普通採樣間隔 |

更短採樣間隔會增加資料量。保留期限越長，需要的存儲通常越多。縮短保留期限前，確認舊資料可以被清理；之後再調長不會恢復已刪除的資料。

## 新資料為什麼可能稍後出現

採樣、日誌批量提交、緩衝寫入和不同實例之間的資料同步是不同環節。固定伺服器部署可查詢該實例的緩衝資料；使用標籤部署時，還可能等待寫入及跨實例同步。

因此，5 秒採樣不等於每個查詢入口都保證在 5 秒內看到資料。排障時檢查實際設定和各組件狀態。

## 修改、停用與排障

修改設定後核對儲存結果、組件版本、存儲連接和新資料。停用組件會影響依賴它的觀測能力，應先確認業務對日誌、指標、自動擴縮容和 AI 分析的使用。

存儲認證失敗時，核對目標位置和金鑰作用域；更換帳戶或位置後不要假設舊秘密字段仍可復用。查詢空結果時檢查時間範圍和保留期限，查詢失敗時保留原始錯誤繼續排查。
