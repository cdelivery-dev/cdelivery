Insight 負責觀測資料的儲存與查詢，收集元件提供伺服器及容器資料。設定需要 Admin，入口位於控制台的 Insight 頁面。

伺服器和容器指標依賴收集元件；歷史觀測資料依賴 Insight 儲存。應用程式日誌還受所選日誌驅動影響；啟用 Insight 不會補採舊日誌。

存取日誌記錄經過 Pingress 的請求。

## 首次啟用

<Steps>

1. 選擇可用的服務端與收集端版本。
2. 選擇儲存類型，並填寫對應位置與驗證資訊。
3. 設定服務端部署位置。
4. 設定保留天數、取樣間隔及緩衝資料寫入間隔。
5. 儲存後檢查服務端和收集端的實際執行狀態。
6. 打開伺服器及應用程式指標，驗證資料開始出現。

</Steps>

## 儲存選項

| 類型 | 需要準備 |
| --- | --- |
| 本地 | 可持久執行的目標伺服器及本機儲存容量 |
| S3 | 區域、儲存貯體、存取金鑰和秘密金鑰 |
| S3 相容 | 額外填寫服務位址，並使用該服務要求的區域 |
| GCS | 儲存貯體與服務帳戶驗證資訊 JSON |
| Azure | 容器名稱、帳戶名稱和帳戶金鑰 |

按儲存服務要求授予讀寫所需權限，並保管驗證資訊。首次啟用後，儲存位置和類型受到限制，主要允許更新區域及認證資訊；本機儲存的部署位置也固定。

## 時間與保留

| 設定 | 介面初始值 | 範圍或含義 |
| --- | --- | --- |
| 保留期限 | 90 天 | 1–3650 天 |
| 取樣間隔 | 5 秒 | 1–60 秒 |
| 寫入間隔 | 3 分鐘 | 控制緩衝資料寫入儲存的時間，按介面單位填寫 |
| 檔案系統取樣 | 5 分鐘 | 獨立於普通取樣間隔 |

更短取樣間隔會增加資料量。保留期限越長，需要的儲存通常越多。

<Aside type="caution">
縮短保留期限前，確認舊資料可以被清理；之後再調長不會恢復已刪除的資料。
</Aside>

取樣、日誌批量提交、緩衝寫入和不同實例之間的資料同步是不同環節。固定伺服器部署可查詢該實例的緩衝資料；使用標籤部署時，還可能等待寫入及跨實例同步。

## 驗證與排障

先選覆蓋故障發生時間的窗口，再逐步縮小。比較日誌、指標和事件時，確保它們針對同一應用程式、同一伺服器和相近時間。

大範圍圖表會按時間桶聚合，圖上的一個點不一定等於單次取樣。應用程式或伺服器剛建立、重新啟動、變更設定後，也可能尚無完整資料窗口。

1. 核對目標對象和時間範圍。
2. 檢查 Insight 及收集元件狀態。
3. 檢查對應日誌驅動或 Pingress 是否實際產生該類資料。
4. 核對儲存連接和保留期限。
5. 查看頁面給出的查詢錯誤，區分查詢失敗和空結果。

從事件定位變更時間，用指標確認影響範圍，再用對應日誌檢查具體錯誤。

修改設定後核對儲存結果、元件版本、儲存連接和新資料。停用元件會影響依賴它的觀測能力，應先確認業務對日誌、指標、自動擴縮容和 AI 分析的使用。

儲存認證失敗時，核對目標位置和金鑰作用域；更換帳戶或位置後不要假設舊機密欄位仍可復用。查詢失敗時保留原始錯誤繼續排查。
