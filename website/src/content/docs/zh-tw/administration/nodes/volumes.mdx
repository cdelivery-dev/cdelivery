資料卷屬於具體伺服器。同名卷出現在不同伺服器上時，也不是同一份資料。刪除應用程式會保留卷，刪除卷才會移除對應的本地資料。

## 啟用與建立

1. 以 Admin 啟用資料卷管理組件；該組件使用獨立的 cdelivery-agent 映像檔。
2. 打開伺服器詳情中的資料卷頁面。
3. 建立卷，填寫名稱和可選說明。名稱遵循平台命名規則，說明最多 256 個字符。
4. 建立[有狀態應用程式](/docs/zh-tw/guides/apps/persistence/stateful/)，選擇同一伺服器，將卷掛載到映像檔要求的資料目錄。
5. 寫入測試資料並重啟應用程式，確認資料仍存在。

卷建立和說明儲存是兩個步驟。如果提示說明儲存失敗，先刷新清單確認卷是否已經建立，再修正說明，避免誤判為整個操作未發生。

## 查看容量

清單可查詢卷大小，並顯示伺服器的總空間與可用空間。大小查詢需要遍歷資料，較大的卷可能花費更長時間；未查詢或未回傳大小不等於卷為空。

平台內部保留的卷不作為普通業務卷管理。卷說明幫助識別用途，但不構成備份，也不證明當前沒有應用程式使用它。

## 刪除與排障

刪除前確認相關應用程式已停止使用卷，並有可恢復的業務備份。不要僅因應用程式已刪除就認為卷中資料無價值。被容器佔用時，先檢查引用和異步退出狀態，再重新刪除。

無法列出卷時，檢查目標伺服器是否在線、卷管理組件是否啟用並正常執行。停用卷管理組件會影響管理能力，不會自動刪除業務卷。卷不存在時核對伺服器 ID 和卷名；不要在另一台機器新建同名卷來代替恢複資料。

資料遷移、資料庫一致性備份和跨伺服器複製需要由業務存儲方案完成。繼續閱讀[資料持久化](/docs/zh-tw/guides/apps/persistence/)。
