CDelivery 主程式、Pingress、Insight、Insight Agent 和資料卷管理元件分別管理版本，需分別更新。

## 更新前檢查

以 Admin 開啟對應元件設定，查看目前版本和可用版本。閱讀發布說明，確認目標機器能拉取映像檔，預留更新時間，並依業務儲存方案完成資料備份。

平台當前按發佈目錄提供最新版本，更新請求要求目標為對應組件的最新版本。控制台不提供任意歷史版本選擇或通用降級按鈕。

## 執行與驗證

<Steps>

1. 在**設定 → CDelivery**選擇可用的新版本並確認更新。
2. 等待主程序重啟，管理頁面可能短暫不可用。
3. 重新打開頁面，確認當前版本已變化。
4. 檢查伺服器、應用程式、事件和 API/MCP 連接。
5. 如其他組件也有更新，分別進入其設定完成並驗證。

</Steps>

Pingress 更新後檢查實際網域與 HTTPS；Insight 更新後確認新日誌和指標繼續出現；採集器更新後檢查伺服器報告是否恢復；資料卷管理更新後驗證卷清單讀取。

平台重新啟動後，重新取得伺服器加入憑證。

## 排障

“無法獲取最新版本”意味著發佈元資料不可用，不能據此判斷已經是最新版。檢查伺服器到發佈服務的網路，再重新查看。

映像檔無法拉取時核對網路、架構與發佈版本；更新後版本未變化時檢查服務任務和事件。應用程式的[發佈回復](/docs/zh-tw/guides/release-safety/rollback/)針對應用程式設定，不是平台版本或業務資料的恢復工具。失去登入能力時參閱[恢復管理存取](/docs/zh-tw/administration/platform/recovery/)。

文字機密在實際部署變更時採用平台隨附的執行階段。僅升級平台不會重新啟動應用；未變更的儲存、描述修改、擴縮及一般重新啟動保留既有參照，回復則還原先前參照。
