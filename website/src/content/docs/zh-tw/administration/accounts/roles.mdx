CDelivery 提供 Reader、Operator、Admin 三種角色，權限依次增加。角色針對整個平台生效，分組不隔離帳戶可見範圍。

## 權限對照

| 能力 | Reader | Operator | Admin |
| --- | --- | --- | --- |
| 查看共享應用程式、伺服器和執行資訊 | 是 | 是 | 是 |
| 管理自己的資料、密碼、消息綁定和 API 金鑰 | 是 | 是 | 是 |
| 修改應用程式、XHealth、XJob、Guardian | 否 | 是 | 是 |
| 管理伺服器、分組、卷和平台設定 | 否 | 否 | 是 |
| 管理其他使用者、簽發伺服器加入憑證 | 否 | 否 | 是 |
| 使用敏感的模型發現操作 | 否 | 否 | 是 |

共享資訊只會脫敏平台明確識別的秘密。日誌、設定檔案和任意環境變數內容不能假定已被自動隱藏，因此 Reader 也應是獲准查看執行資料的可信使用者。

## 不同入口如何生效

瀏覽器會話使用帳戶的當前角色。API 金鑰的有效角色取“帳戶當前角色”和“金鑰角色上限”中較低者；降級帳戶會立即限制其金鑰，升級帳戶不會提高舊金鑰上限。

REST、MCP、控制台和使用者發起的 AI 工具操作遵循同一授權規則。通過消息渠道綁定的身份使用對應帳戶的當前權限。自動值班使用管理員設定的獨立值班角色，預設 Reader，不能存取某個使用者的個人帳戶操作。

## 分配與驗證

為觀察者選擇 Reader，為日常發佈人員選擇 Operator，僅為需要管理平台的人選擇 Admin。建立或調整後，用目標帳戶檢查能看到的資料和可用操作，再連接自動化工具。

Admin 不能刪除自己或降低自己的角色。密碼修改會使全部瀏覽器會話失效，但不會撤銷 API 金鑰；完整交接還需檢查[使用者管理](/docs/zh-tw/administration/accounts/users/)和[API 金鑰](/docs/zh-tw/guides/automation/api-mcp/)。
