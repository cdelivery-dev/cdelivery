## Initialization order

After creating the first Admin, verify server addresses and state, then create groups and applications. Give team members separate accounts and suitable roles. Add domains, collection, message channels, and AI as needed.

Groups do not isolate account permissions, and labels do not replicate data. Check application and component dependencies before changing placement or removing a resource.

## Verify management changes

A successful request can precede container replacement, server joining, or fresh collection. Inspect the resource list, runtime state, events, and actual access separately.

For backup and recovery, verify business data rather than only checking that a container runs. The guides explain which resources remain after deletion so cleanup can be performed deliberately.
