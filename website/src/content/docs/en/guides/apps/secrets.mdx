Secrets store passwords, tokens and credential files for your applications. Create a secret once and reuse it across applications in different groups.

| Type | Use |
| --- | --- |
| Text | Pass a value to the application as an environment variable, such as an API token. |
| File | Mount a read-only file through XConfig, such as a credentials configuration file. |

## Create a secret

Creating, using and deleting secrets requires Operator or Admin. Reader can view names, types and descriptions.

<Steps>

1. Open **Secrets** in the sidebar and select **Create**.
2. Choose **Text** or **File**, enter a name and optionally add a description.
3. Enter the text or select a local file to upload.
4. Select **Create** and confirm that the secret appears in the list.

</Steps>

Content must be nonempty and smaller than 500 KiB. Descriptions accept up to 64 characters. Text supports multiple lines and preserves whitespace and trailing newlines.

After creation, content cannot be viewed, downloaded or edited through the platform. To change it, create a new secret and update the application's selection.

Names and descriptions are visible to accounts with read access. If an application writes secret content to its logs, that content remains visible in those logs.

## Use a secret in an application

### As an environment variable

<Steps>

1. Open the application's create or configuration page and add an environment variable.
2. Enter the variable name, such as `API_TOKEN`, and switch the source to **Secret**.
3. Select an existing Text secret, such as `api-token`, and confirm the entry.
4. Save the entire application configuration, wait for deployment, then verify that the application can access the intended service.

</Steps>

### As a mounted file

<Steps>

1. Add a configuration file in the application's file and storage settings.
2. Enter the container file path, such as `/etc/app/credentials.json`.
3. Switch the source to **Secret**, select an existing File secret and confirm.
4. Save the application configuration, wait for deployment, then verify that the application can read the file.

</Steps>

Files are mounted read-only. Applications with local data volumes can also use File secrets. Prefer a File secret for larger configuration content.

## Replace and delete

<Steps>

1. Create the replacement under a new name, such as `api-token-v2`.
2. Edit each application that needs the replacement, select the new secret and save.
3. Once the new deployments work as expected, return to the Secrets list and delete the unused secret.

</Steps>

Deletion is refused while a current application, running task or available rollback configuration still uses the secret. Delete it after those uses have ended.
