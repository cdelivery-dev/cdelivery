## Create and bind

Create a Text secret for an environment variable, or a File secret for an XConfig mount. Create it on the Secrets page before selecting it in the application's configuration.

## Permissions

Reader can list metadata. Operator and Admin can create, delete and bind secrets. Content cannot be read back, downloaded or edited.

## Limits

Content must be nonempty and at most 511,999 bytes; descriptions accept 64 characters. Text preserves whitespace and trailing newlines and rejects NUL. File supports binary content. Large content belongs in a file: the operating system's process environment limits can be smaller than the storage limit.

## Replace and delete

To replace a credential, create a new name, update each application's reference, and verify the deployment. Delete the old resource only after current tasks and rollback configurations no longer need it. References include name and ID: recreating a name does not replace old references.

## Runtime behavior

File mounts are read-only with mode 0444. Local-volume applications support File secrets, although ordinary XConfig uploads remain unavailable. XJob, XHealth, Hurl and Guardian inherit bindings; candidate checks use candidate references. Ordinary exec sessions do not automatically inherit startup-injected variables.

## Visibility

Names and descriptions are visible metadata. Applications and their tasks can access the content and can expose it in logs; secret storage does not automatically redact logs. Keep your own protected source copy. Existing plain environment values and uploads are not converted automatically.
