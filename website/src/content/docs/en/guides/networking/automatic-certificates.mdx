Automatic HTTPS uses ACME to issue and renew certificates. An Admin configures this capability; application routes still need correct domains and HTTPS settings.

## Prepare and enable

Point each domain at a reachable Pingress entry server and allow ports 80 and 443. With the default HTTP-01 method, the validation request must reach Pingress on port 80.

Check its health endpoint:

```sh
curl -i http://app.example.com/.well-known/acme-challenge/healthz
```

Expect HTTP 200 without relying on redirects. Fix DNS, IPv6 records, proxies, and firewall rules before requesting a certificate.

Automatic certificates are selected by default when enabling Pingress. You can also enable them later in the certificate settings.

The creation API defaults to `"acme": "LetsEncrypt"`; use `"acme": null` for HTTP-only or manually managed certificates. This clears any retained account and automatic certificates, keeping uploaded certificates. Staging and Pebble are testing options, not publicly trusted production certificates. The API also supports dns-persist-01 where the selected authority supports it; this is not a generic DNS-provider integration form. See [ACME challenge types](https://letsencrypt.org/docs/challenge-types/).

## Issuance and renewal

Certificates are issued in the background. Issuance is checked approximately every five minutes and renewal every eight hours. Renewal timing follows the authority's renewal information when available or the certificate's validity window.

Automatic renewal requires continued validation access. Manually uploaded certificates are not automatically renewed.

## Verify and troubleshoot

Inspect the certificate's domain, issuer, and expiry from a real client. Test both IPv4 and IPv6 if DNS publishes both. A stale AAAA record can break validation even when IPv4 works.

The automatic-certificate account is prepared before Pingress is deployed. If deployment fails, the account is retained for retry. Before Pingress exists, you can select another supported authority through the API if no automatic certificates are stored.

For failures, check the exact domain, challenge endpoint, authority environment, network, and reported error. Avoid repeated requests before fixing the cause. Use [custom certificates](/docs/guides/networking/custom-certificates/) when you manage issuance yourself.
