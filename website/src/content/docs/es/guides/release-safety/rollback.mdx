La reversión recupera configuración previa, no datos ni versiones de la plataforma.

## Decidir

Comprueba si la imagen anterior puede utilizar los datos actuales. Una migración puede necesitar restauración propia antes de volver a una versión antigua.

Usa la acción de reversión cuando exista configuración anterior. También puede iniciarse por la estrategia automática de fallos.

La reversión sustituye tareas en paralelo y usa Continue ante sus propios fallos; conserva ajustes relevantes de orden, observación y proporción.

## Verificar

1. Comprueba configuración e imagen resultantes.
2. Compara réplicas deseadas y reales.
3. Lee registros.
4. Prueba servicio y datos.
5. Revisa XHealth y eventos.

Si no existe configuración previa, reconstruye una versión conocida con tus registros. Recrear el nombre no recupera historial.

## Si sigue fallando

Comprueba capacidad, registro, credenciales, almacenamiento y compatibilidad. Repetir la acción no arregla un registro inaccesible.

Las acciones de [Guardian](/docs/es/guides/release-safety/guardian/) controlan el candidato. Las [actualizaciones de plataforma](/docs/es/administration/platform/upgrades/) son independientes.

[Secretos](/docs/es/guides/apps/secrets/): Para sustituir un secreto, créelo con otro nombre, actualice las referencias de cada aplicación y verifique el despliegue. Elimine el anterior cuando las tareas y las configuraciones de reversión dejen de necesitarlo. Las referencias incluyen nombre e ID; recrear un nombre no sustituye las referencias antiguas.
