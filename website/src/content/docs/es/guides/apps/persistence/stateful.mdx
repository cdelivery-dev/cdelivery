El modo con datos locales fija una réplica a un servidor y se selecciona durante la creación.

## Crear

<Steps>

1. Elige servidor y comprueba espacio.
2. Crea o identifica [su volumen](/docs/es/administration/nodes/volumes/).
3. Selecciona imagen o plantilla.
4. Revisa variables y credenciales.
5. Monta el directorio de datos correcto.
6. Arranca y escribe datos de prueba.

</Steps>

Este modo no utiliza ubicación dinámica, escalado automático, cargas XConfig normales. Las comprobaciones de publicación requieren volúmenes ZFS. La plantilla de PostgreSQL 18 monta `/var/lib/postgresql` y conserva el `PGDATA` predeterminado de la imagen. MariaDB 12 monta `/var/lib/mysql`. Al cambiar la imagen o las variables de entorno, comprueba el directorio de datos y las reglas de inicialización.

Las aplicaciones con volúmenes locales también pueden montar archivos de [Secretos](/docs/es/guides/apps/secrets/) de solo lectura para proporcionar credenciales.

Las credenciales de plantilla son configuración de aplicación; no supongas que todas las variables están ocultas.

## Actualizar

<Aside type="caution">
Una réplica puede quedar indisponible al sustituirse. Revisa [estrategia](/docs/es/guides/release-safety/update-strategy/) y requisitos del proveedor. No ejecutes versiones incompatibles contra el mismo directorio.
</Aside>

Antes de cambiar el formato de los datos, crea una copia de seguridad consistente y comprueba que puedes restaurarla. La [reversión](/docs/es/guides/release-safety/rollback/) recupera configuración, no datos.

## Recuperar

Un servidor distinto con un volumen homónimo no recupera información. Migra o restaura los datos y verifica la nueva instalación. Al eliminar la aplicación se conserva el volumen; registra servidor y nombre antes de limpiar.
