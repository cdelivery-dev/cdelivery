Los secretos almacenan contraseñas, tokens y archivos de credenciales para tus aplicaciones. Puedes crearlos una vez y reutilizarlos en aplicaciones de distintos grupos.

| Tipo | Uso |
| --- | --- |
| Texto | Pasa un valor a la aplicación mediante una variable de entorno, como un token de API. |
| Archivo | Monta un archivo de solo lectura mediante XConfig, como una configuración de credenciales. |

## Crear un secreto

Crear, usar y eliminar secretos requiere Operator o Admin. Reader puede consultar nombres, tipos y descripciones.

<Steps>

1. Abre **Secretos** en la barra lateral y selecciona **Crear**.
2. Elige **Texto** o **Archivo**, introduce un nombre y, si lo necesitas, una descripción.
3. Escribe el contenido o selecciona un archivo local para cargar.
4. Selecciona **Crear** y comprueba que el secreto aparece en la lista.

</Steps>

El contenido no puede estar vacío y debe ocupar menos de 500 KiB. La descripción admite hasta 64 caracteres. El texto admite varias líneas y conserva los espacios y los saltos de línea finales.

Una vez creado, el contenido no se puede ver, descargar ni editar desde la plataforma. Para cambiarlo, crea otro secreto y actualiza la selección de la aplicación.

Los nombres y las descripciones son visibles para las cuentas con acceso de lectura. Si la aplicación escribe el contenido en los logs, seguirá siendo visible en ellos.

## Usar en una aplicación

### Como variable de entorno

<Steps>

1. En la página de creación o configuración de la aplicación, añade una variable de entorno.
2. Introduce el nombre, por ejemplo `API_TOKEN`, y cambia el origen a **Secreto**.
3. Selecciona un secreto de texto existente, como `api-token`, y confirma la entrada.
4. Guarda toda la configuración de la aplicación, espera al despliegue y verifica el acceso al servicio correspondiente.

</Steps>

### Como archivo montado

<Steps>

1. Añade un archivo de configuración en las opciones de archivos y almacenamiento de la aplicación.
2. Introduce la ruta del archivo dentro del contenedor, como `/etc/app/credentials.json`.
3. Cambia el origen a **Secreto**, selecciona un secreto de archivo existente y confirma.
4. Guarda la configuración, espera al despliegue y comprueba que la aplicación puede leer el archivo.

</Steps>

Los archivos se montan en modo de solo lectura. Las aplicaciones con volúmenes de datos locales también pueden usarlos. Para configuraciones grandes, elige un secreto de archivo.

## Sustituir y eliminar

<Steps>

1. Crea el contenido nuevo con otro nombre, como `api-token-v2`.
2. Edita cada aplicación que necesite el cambio, selecciona el nuevo secreto y guarda.
3. Tras verificar los nuevos despliegues, vuelve a la lista y elimina el secreto que ya no se usa.

</Steps>

La eliminación se rechaza mientras una aplicación actual, una tarea en ejecución o una configuración disponible para rollback siga usando el secreto. Elimínalo cuando esos usos hayan terminado.
