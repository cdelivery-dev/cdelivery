実行候補のサーバーと、1 台当たりのレプリカ上限を指定します。

## 設定

Admin が[ラベル](/docs/ja/administration/nodes/labels/)を付け、アプリで選択します。上限と予約を確認して保存します。

3 レプリカを 1 台 1 個までとするなら、準備済み・配置可能・資源十分な候補が 3 台必要です。ラベルは所属条件で、複雑な検索式ではありません。状態を持つアプリは固定サーバーです。

## 変更

制約の変更は置換や移動を起こす場合があります。StartFirst は余分な容量を必要とします。

配置はファイルやボリュームをコピーしません。同じラベルや名前でも元データは利用できません。[ローカルデータ方式](/docs/ja/guides/apps/persistence/stateful/)を参照してください。

## 検証

実際の分布、ラベル、可用性、予約、上限を確認します。再起動を繰り返す前にタスクのエラーを読みます。

再参加したサーバーは ID が変わる場合があるため、固定指定とラベルを[サーバー管理](/docs/ja/administration/nodes/)で確認します。
