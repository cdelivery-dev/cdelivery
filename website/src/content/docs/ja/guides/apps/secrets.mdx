シークレットには、アプリで使うパスワード、トークン、認証情報ファイルを保存できます。一度作成すると、異なるグループのアプリでも再利用できます。

| 種類 | 用途 |
| --- | --- |
| テキスト | API トークンなどの値を環境変数としてアプリに渡します。 |
| ファイル | 認証情報の設定ファイルなどを XConfig で読み取り専用マウントします。 |

## シークレットを作成する

作成、使用、削除には Operator または Admin が必要です。Reader は名前、種類、説明を確認できます。

<Steps>

1. サイドバーの**シークレット**を開き、**作成**を選びます。
2. **テキスト**または**ファイル**を選び、名前と必要に応じて説明を入力します。
3. テキストを入力するか、アップロードするローカルファイルを選びます。
4. **作成**を選び、一覧にシークレットが表示されることを確認します。

</Steps>

内容は空にできず、500 KiB 未満である必要があります。説明は最大 64 文字です。テキストは複数行に対応し、空白や末尾の改行も保持します。

作成後は、プラットフォームから内容を表示、ダウンロード、編集できません。変更する場合は新しいシークレットを作成し、アプリで選び直します。

名前と説明は読み取り権限のあるアカウントに表示されます。アプリが内容をログに出力した場合、その内容はログに残ります。

## アプリで使用する

### 環境変数として使う

<Steps>

1. アプリの作成ページまたは設定ページで環境変数を追加します。
2. `API_TOKEN` などの変数名を入力し、ソースを**シークレット**に切り替えます。
3. `api-token` などの作成済みテキストシークレットを選び、確定します。
4. アプリ設定全体を保存し、デプロイ後に対象サービスへ接続できることを確認します。

</Steps>

### ファイルとしてマウントする

<Steps>

1. アプリのファイルとストレージ設定で設定ファイルを追加します。
2. `/etc/app/credentials.json` など、コンテナ内のファイルパスを入力します。
3. ソースを**シークレット**に切り替え、作成済みファイルシークレットを選んで確定します。
4. アプリ設定を保存し、デプロイ後にアプリがそのファイルを読み取れることを確認します。

</Steps>

ファイルは読み取り専用でマウントされます。ローカルデータボリュームを使うアプリでも利用できます。大きな設定内容にはファイルシークレットが適しています。

## 置き換えと削除

<Steps>

1. `api-token-v2` などの新しい名前で、置き換える内容を作成します。
2. 対象の各アプリを編集し、新しいシークレットを選んで保存します。
3. 新しいデプロイの動作を確認してから、シークレット一覧で不要になったものを削除します。

</Steps>

現在のアプリ、実行中のタスク、または利用可能なロールバック設定で使用されている間は削除できません。それらで使われなくなってから削除してください。
