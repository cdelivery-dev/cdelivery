同じグループのアプリは名前とコンテナーポートで接続します。

## 内部通信

例は `database:5432` です。コンテナー内の localhost は自分自身です。接続先は通常 `0.0.0.0` など、他から届くインターフェースで待受します。

異なるグループの名前解決は前提にしません。グループのネットワークはアカウント権限境界ではありません。

## 公開

TCP/UDP と内部・公開ポートを指定します。Nginx なら 80 → 8080/TCP。保存後タスクと `http://SERVER_IP:8080` を確認します。

ホストとクラウドのファイアウォール、SSH の追加転送を確認します。ポート設定は待受プロセスを起動せず、TCP を HTTP に変換もしません。

## 調査

プロセス、待受アドレス、ポート、所属グループ、サーバー間通信を確認します。公開経路ではプロトコル、IP、ファイアウォールも調べます。

[ドメインルート](/docs/ja/guides/networking/routing/)は内部ポートを使います。IPv6 は [FAQ](/docs/ja/guides/networking/faq/) を参照してください。
