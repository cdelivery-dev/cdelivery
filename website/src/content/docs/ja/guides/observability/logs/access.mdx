Pingress 経由の要求を記録し、公開ポートへの直接接続とは区別します。

## 確認項目

アプリ・ドメイン・期間を選び、結果、入口サーバー、宛先ポート、バイト、最初の応答までの時間、エラーを確認します。

要求なしは DNS・プロキシ・条件・収集、TLS は証明書、バックエンドはタスク・待受・ポート、誤ルートは名前・接頭辞・ヘッダー/Cookie、遅延は処理・依存先・転送を調べます。

クライアント IP が直接の相手やプロキシを示す場合があります。経路を理解せず元利用者と断定しません。

## 検証

[ルート](/docs/ja/guides/networking/routing/)変更後、一致する要求としない要求を送り、宛先と結果を比較します。

時刻を[アプリログ](/docs/ja/guides/observability/logs/application/)や指標と照合します。稼働中プロセスでも HTTP は失敗し得ます。

履歴不足は Insight、収集器、保存先、[期限](/docs/ja/guides/observability/settings/)を確認します。
