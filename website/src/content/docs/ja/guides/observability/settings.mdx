Admin が Insight、収集器、保存先、保存期間を設定します。

## 収集を有効にする

<Steps>

1. サービスと収集器のバージョンを選択します。
2. 保存先の種類、場所、認証情報を設定します。
3. サービスの配置先を設定します。
4. 保持期間、収集間隔、flush 間隔を設定します。
5. 保存し、サービスと収集器の実行状態を確認します。
6. サーバーとアプリの指標を開き、新しいデータが表示されることを確認します。

</Steps>

## 保存先と配置

Local、S3、endpoint 付き S3-compatible、サービスアカウント JSON の GCS、Azure を選びます。保存対象と認証を有効化前に準備します。

有効化後、種類や保存先識別は通常編集で移行できません。認証情報や対応する region は変更可能です。Local は固定サーバーが必要で、移行とバックアップは別途計画します。

## 収集間隔と保持期間

保持は標準 90 日、範囲 1–3650 日。測定は標準 5 秒、範囲 1–60 秒。flush は標準 3 分。ファイルシステムは 5 分です。

固定サーバーはバッファーを参照できます。ラベルによる分散配置は flush と同期を待つ場合があります。高頻度・長期保存ほど容量が必要です。

<Aside type="caution">
保持期間を短縮すると履歴が削除される場合があります。後から延長しても削除済みデータは戻りません。
</Aside>

## 検証とトラブルシューティング

対象、ソース、期間を選びます。履歴クエリーは最大 31 日で、調査では発生時刻付近に絞ります。

空は活動なし、遅延、未収集、期限切れの可能性があります。クエリー失敗と区別し、欠測をゼロと扱いません。

新しい活動を発生させ、各サーバーのログ・指標・イベントを確認します。過去分の自動取り込みはありません。

欠落はコンポーネント、通信、認証、期間を調べます。[ログドライバー](/docs/ja/guides/observability/logs/application/)は別設定です。
