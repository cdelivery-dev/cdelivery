XHealth は独立したコンテナでアプリを検証し、[シークレット](/docs/ja/guides/apps/secrets/)を含むアプリの環境変数とファイルマウントを使用します。Operator と Admin が設定し、Reader は共有結果を確認できます。

## 対象を選ぶ

アプリの **XHealth** ページで Hurl またはカスタムコマンド、対象、1 分以上の間隔を選びます。定期チェックと**今すぐ実行**は同じ対象を使用します。

| 対象 | アドレス | ポート | プロトコル |
| --- | --- | --- | --- |
| ドメイン | DNS で解決したドメイン | 80 または 443 | HTTP、ドメインで HTTPS が有効なら HTTPS |
| 公開ポート | サーバー IP | 選択した公開ポート | Hurl は HTTP、カスタムコマンドは任意 |
| コンテナ内ポート | アプリの内部アドレス | 指定したコンテナポート | Hurl は HTTP、カスタムコマンドは任意 |

同じドメインのいずれかのルートで HTTPS が有効なら HTTPS を使用します。ドメインと公開ポートはこのアプリに属し、内部ポートが一意である必要があります。リリース検証を無効にしても同じです。同じポートを指す複数のルートは使用できます。Hurl のポートマッピングは TCP のみです。HTTP 以外のサービスにはカスタムコマンドとポート指定を使います。

## Hurl

Hello の例ではコンテナ内ポート `80` を選び、次のファイルをアップロードします。

```hurl
GET {{TARGET_URL}}/
HTTP 200
```

`{{TARGET_URL}}` は `HURL_VARIABLE_TARGET_URL` から対象 URL を受け取ります。ファイルは空にできず、上限は 1,023,999 バイトです。更新時に未選択なら現在のファイルを保持します。[Hurl の構文](https://hurl.dev/docs/request.html)を参照してください。

認証にはテキストシークレットを `HURL_VARIABLE_API_TOKEN` に設定し、ファイル内で `{{API_TOKEN}}` を使えます。

## カスタムコマンド

アプリのイメージに必要なツールを含めてください。終了コード 0 は成功、それ以外は失敗です。`localhost` はチェック用コンテナを指します。

`TARGET_HOST` と `TARGET_PORT` が対象を示します。ドメイン指定では `TARGET_SCHEME`（`http` または `https`）も設定されます。変数の展開やパイプにはシェルを明示します。引数はシェル形式の引用符とエスケープに対応します。

イメージに `sh` と `wget` がある場合：

```sh
sh -c 'wget -q -O /dev/null "${TARGET_SCHEME:-http}://${TARGET_HOST}:${TARGET_PORT}/"'
```

プラットフォームが設定する対象変数は同名の通常値を上書きし、シークレットや依存関係の出力を割り当てることはできません。`/xhealth.hurl` は Hurl 用に空けてください。チェックは読み取り専用にし、実際の業務条件を検証します。

## 今すぐ実行

有効なチェックで**今すぐ実行**を選ぶか、本文なしの `POST /api/apps/{name}/xhealth/run`、または `app` を指定した `xhealth_run` を使います。保存済みの設定で実行し、次の間隔は今回の開始時から計算します。

API は受理時に `202` と `{"ok":true}`、待機中・実行中なら `409` を返します。[状態とログ](/docs/ja/guides/release-safety/xhealth/status/)または `xhealth_get` で結果を確認します。応答を受け取れなかった場合は再要求前に状態を確認してください。完了後の要求は新たな実行を開始します。

## リリース検証

**リリース検証に参加**を有効にすると、アプリ自身や直接の依存先を更新する際、プレビューサービスの内部ポートを検証します。Hurl は HTTP を使用し、ドメイン指定のカスタムチェックには `TARGET_SCHEME=http` が設定されます。本番の定期チェックは独立して継続します。

設定手順と例は[アプリ間の依存関係](/docs/ja/guides/apps/dependencies/app/)と [PostgreSQL の依存関係](/docs/ja/guides/apps/dependencies/postgresql/)を参照してください。
