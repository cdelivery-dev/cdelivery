## 状態

| 状態 | 意味 |
| --- | --- |
| Pending | 実行待ち |
| Running | チェック実行中 |
| Passed | チェック成功 |
| Failed | チェック失敗。エラーとログを確認 |
| Settled | 利用できる成功・失敗の結果なしで終了 |

成功を示すのは Passed だけです。完了時刻を確認し、古い結果を現在の状態と混同しないでください。

## 失敗を調べる

最新の[アプリログ](/docs/ja/guides/observability/logs/application/)で XHealth を選びます。待機が続く場合はサーバー資源とイメージ取得、長時間実行ではタイムアウトやコマンドの停止、失敗ではツール、変数、Hurl のアサーションを確認します。

接続エラーは選択した対象に沿って調べます。

| 対象 | 確認する項目 |
| --- | --- |
| ドメイン | チェック用コンテナの DNS、プロキシルート、HTTP/HTTPS、証明書の信頼 |
| 公開ポート | サーバー IP への到達性、ポートマッピング、ファイアウォール |
| コンテナ内ポート | アプリの内部アドレス、グループネットワーク、待受ポート、起動状態 |

対象が見つからない、または曖昧な場合は、アプリ設定と内部ポートの一意性を確認します。結果はチェック用コンテナからのアクセスを表し、外部クライアントの経路とは異なる場合があります。

## 変更後の確認

再実行し、新しい Passed 結果を確認します。プロセスの存在だけでなく業務の利用可能性を検証してください。

リリース失敗時は、本番 XHealth と分けてプレビューサービスとそのチェックログを確認します。アラートは[通知設定](/docs/ja/guides/automation/im/notifications/)で設定します。

対象とコマンドの規則は [XHealth の設定](/docs/ja/guides/release-safety/xhealth/)を参照してください。
