REST und MCP teilen Operationen und Autorisierung; alle Pfade gehören zu deiner Instanz.

## Schlüssel

Unter Konto → MCP/API keys Namen mit 1–64 UTF-8-Bytes, Rollenobergrenze und optional zukünftiges Ablaufdatum setzen. Sofort kopieren, einmalige Anzeige.

Je Werkzeug eigener Schlüssel. Rolle kann wirksame Erstellungsrolle nicht übersteigen und bleibt durch aktuelle Nutzerrolle begrenzt. Passwortwechsel erhält Schlüssel; Nutzerlöschung invalidiert ihn.

## REST

URL/Schlüssel lokal setzen:

```sh
curl --fail-with-body "$CDELIVERY_URL/api/me" \
  -H "Authorization: Bearer $CDELIVERY_API_KEY"
```

Eigene Kontodaten erwarten. `/scalar` zeigt das installierte Schema.

Patch: ausgelassen behält Wert, `null` leert nur geeignete Felder, leerer Patch gültig. Enums unterscheiden Groß-/Kleinschreibung: Reader/Operator/Admin.

## MCP

Richte den HTTP-Client auf `/mcp` mit `Authorization: Bearer YOUR_API_KEY`. Liste die Werkzeuge auf und prüfe Konto und Rechte mit einem lesenden Aufruf vor Schreibzugriffen.

## Fehler

401: ungültig/abgelaufen/widerrufen oder Nutzer unzugänglich. 403: Rechte. 422: Felder/Voraussetzungen. Verbindung: URL/TLS/Proxy.

Nach Widerruf Ablehnung testen. Siehe [Rollen](/docs/de/administration/accounts/roles/).

[Geheimnisse](/docs/de/guides/apps/secrets/): Reader dürfen Metadaten auflisten. Operator und Admin dürfen Geheimnisse erstellen, löschen und zuordnen. Inhalte lassen sich weder zurücklesen noch herunterladen oder bearbeiten.


| REST | MCP / Agent |
| --- | --- |
| `POST /api/secrets` | `secret_create` |
| `GET /api/secrets?kind=Text` | `secret_list` |
| `DELETE /api/secrets/{name}` | `secret_delete` |

`POST /api/secrets`:

```json
{"name":"api-token","content":{"Text":"REPLACE_LOCALLY"}}
```

- `content.File`: Base64.
- `container_options.env`: `[{"name":"TOKEN","value":{"name":"api-token","id":"SECRET_ID"}}]`.
- `POST /api/apps` → `xconfigs`: `[{"target":"/app/credentials","secret":{"name":"api-file","id":"SECRET_ID"}}]`.
- `PATCH /api/apps/{name}` → `xconfigs`: `[{"Secret":{"target":"/app/credentials","secret":{"name":"api-file","id":"SECRET_ID"}}}]`.
