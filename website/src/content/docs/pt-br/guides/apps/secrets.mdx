Segredos armazenam senhas, tokens e arquivos de credenciais dos aplicativos. Crie uma vez e reutilize em aplicativos de diferentes grupos.

| Tipo | Uso |
| --- | --- |
| Texto | Passe um valor ao aplicativo por uma variável de ambiente, como um token de API. |
| Arquivo | Monte um arquivo somente para leitura pelo XConfig, como uma configuração de credenciais. |

## Criar um segredo

Criar, usar e excluir segredos exige Operator ou Admin. Reader pode consultar nomes, tipos e descrições.

<Steps>

1. Abra **Segredos** na barra lateral e selecione **Criar**.
2. Escolha **Texto** ou **Arquivo**, informe um nome e, se quiser, uma descrição.
3. Digite o conteúdo ou selecione um arquivo local para enviar.
4. Selecione **Criar** e confira se o segredo aparece na lista.

</Steps>

O conteúdo não pode estar vazio e deve ter menos de 500 KiB. A descrição aceita até 64 caracteres. Textos podem ter várias linhas; espaços e quebras de linha finais são preservados.

Após a criação, não é possível visualizar, baixar ou editar o conteúdo pela plataforma. Para alterá-lo, crie outro segredo e atualize a seleção do aplicativo.

Nomes e descrições ficam visíveis para contas com acesso de leitura. Se o aplicativo escrever o conteúdo nos logs, ele continuará visível nesses logs.

## Usar no aplicativo

### Como variável de ambiente

<Steps>

1. Na página de criação ou configuração do aplicativo, adicione uma variável de ambiente.
2. Informe o nome, como `API_TOKEN`, e mude a origem para **Segredo**.
3. Selecione um segredo de texto existente, como `api-token`, e confirme a entrada.
4. Salve toda a configuração do aplicativo, aguarde o deploy e confirme o acesso ao serviço desejado.

</Steps>

### Como arquivo montado

<Steps>

1. Adicione um arquivo de configuração nas opções de arquivos e armazenamento do aplicativo.
2. Informe o caminho do arquivo no contêiner, como `/etc/app/credentials.json`.
3. Mude a origem para **Segredo**, selecione um segredo de arquivo existente e confirme.
4. Salve a configuração, aguarde o deploy e confira se o aplicativo consegue ler o arquivo.

</Steps>

Os arquivos são montados somente para leitura. Aplicativos com volumes de dados locais também podem usar segredos de arquivo. Prefira esse tipo para configurações maiores.

## Substituir e excluir

<Steps>

1. Crie o novo conteúdo com outro nome, como `api-token-v2`.
2. Edite cada aplicativo que precisa da alteração, selecione o novo segredo e salve.
3. Depois de verificar os novos deploys, volte à lista de segredos e exclua o que não é mais usado.

</Steps>

A exclusão é recusada enquanto um aplicativo atual, uma tarefa em execução ou uma configuração disponível para rollback ainda usa o segredo. Exclua-o quando esses usos terminarem.
