Programme principal, Pingress, Insight, Insight Agent et gestion des volumes ont des versions indépendantes.

## Préparer

Admin consulte les versions et les notes de publication. Vérifiez le registre, l’architecture et le temps disponible. Sauvegardez les données.

Le catalogue fournit la dernière version et les demandes l’exigent. Aucun sélecteur général d’historique ou bouton universel de rétrogradation.

## Actualiser

Choisissez la version dans Paramètres → CDelivery, confirmez et attendez le redémarrage. Contrôlez ensuite version, serveurs, applications, événements et API/MCP.

Actualisez chaque composant séparément. Testez HTTPS après Pingress, nouvelles mesures après Insight/collecteurs, volumes après l’agent. Renouvelez invitations serveur après redémarrage.

## Diagnostic

Métadonnées indisponibles ne signifient pas à jour. Vérifiez accès au service de publication. Pull échoué : image, architecture, tâches.

[Rollback applicatif](/docs/fr/guides/release-safety/rollback/) ne restaure ni plateforme ni données. Voir [récupération](/docs/fr/administration/platform/recovery/) pour login.

Les secrets texte utilisent le runtime fourni lors d’un changement effectif de déploiement. Une mise à jour de la plateforme seule ne redémarre pas les applications. Une sauvegarde sans changement, la description, la mise à l’échelle et un redémarrage ordinaire conservent les références ; un retour arrière restaure les précédentes.
