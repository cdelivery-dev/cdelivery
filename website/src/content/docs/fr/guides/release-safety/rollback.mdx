Rollback restaure une configuration précédente, pas les données ou la plateforme.

## Décider

Vérifiez que l’ancienne image accepte les données actuelles. Une migration peut nécessiter restauration métier avant de relancer l’ancienne version.

Utilisez rollback lorsqu’une configuration antérieure existe, ou laissez la stratégie le déclencher. Il remplace en parallèle avec Continue pour ses propres échecs, en conservant les paramètres pertinents d’ordre, observation et proportion.

## Contrôler

Vérifiez configuration/image, réplicas, journaux, requête, données, XHealth et événements.

Sans historique disponible, reconstruisez une configuration connue. Recréer un nom ne restaure pas l’ancienne identité.

## Échec persistant

Contrôlez capacité, registre, secrets, stockage et compatibilité. Répéter ne répare pas une dépendance inaccessible.

Les actions [Guardian](/docs/fr/guides/release-safety/guardian/) concernent son candidat ; la [maintenance plateforme](/docs/fr/administration/platform/upgrades/) est distincte.

[Secrets](/docs/fr/guides/apps/secrets/): Pour remplacer un secret, créez un nouveau nom, modifiez les références de chaque application et vérifiez le déploiement. Supprimez l’ancien uniquement quand les tâches et les configurations de retour arrière ne l’utilisent plus. Une référence contient le nom et l’ID ; recréer le même nom ne remplace pas les anciennes références.
