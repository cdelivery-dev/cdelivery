Les secrets conservent les mots de passe, jetons et fichiers d’identifiants de vos applications. Créez-les une fois, puis réutilisez-les dans des applications de différents groupes.

| Type | Utilisation |
| --- | --- |
| Texte | Transmettre une valeur à l’application par une variable d’environnement, comme un jeton d’API. |
| Fichier | Monter un fichier en lecture seule via XConfig, comme un fichier d’identifiants. |

## Créer un secret

La création, l’utilisation et la suppression nécessitent Operator ou Admin. Reader peut consulter les noms, types et descriptions.

<Steps>

1. Ouvrez **Secrets** dans la barre latérale et sélectionnez **Créer**.
2. Choisissez **Texte** ou **Fichier**, saisissez un nom et, si besoin, une description.
3. Saisissez le contenu ou choisissez un fichier local à téléverser.
4. Sélectionnez **Créer** et vérifiez que le secret apparaît dans la liste.

</Steps>

Le contenu doit être non vide et inférieur à 500 Kio. La description accepte jusqu’à 64 caractères. Le texte peut contenir plusieurs lignes ; les espaces et les sauts de ligne finaux sont conservés.

Après la création, le contenu ne peut être ni consulté, ni téléchargé, ni modifié depuis la plateforme. Pour le changer, créez un nouveau secret et sélectionnez-le dans l’application.

Les noms et descriptions sont visibles par les comptes disposant d’un accès en lecture. Si l’application écrit le contenu dans ses journaux, celui-ci reste visible dans ces journaux.

## Utiliser dans une application

### Comme variable d’environnement

<Steps>

1. Dans la page de création ou de configuration de l’application, ajoutez une variable d’environnement.
2. Saisissez son nom, par exemple `API_TOKEN`, et choisissez la source **Secret**.
3. Sélectionnez un secret texte existant, comme `api-token`, puis confirmez l’entrée.
4. Enregistrez toute la configuration, attendez le déploiement, puis vérifiez l’accès de l’application au service concerné.

</Steps>

### Comme fichier monté

<Steps>

1. Ajoutez un fichier de configuration dans les réglages de fichiers et de stockage de l’application.
2. Saisissez le chemin du fichier dans le conteneur, par exemple `/etc/app/credentials.json`.
3. Choisissez la source **Secret**, sélectionnez un secret fichier existant et confirmez.
4. Enregistrez la configuration, attendez le déploiement et vérifiez que l’application peut lire le fichier.

</Steps>

Les fichiers sont montés en lecture seule. Les applications utilisant des volumes de données locaux peuvent aussi les utiliser. Préférez un secret fichier pour les configurations volumineuses.

## Remplacer et supprimer

<Steps>

1. Créez le nouveau contenu sous un autre nom, par exemple `api-token-v2`.
2. Modifiez chaque application concernée, sélectionnez le nouveau secret et enregistrez.
3. Après avoir vérifié les nouveaux déploiements, revenez à la liste et supprimez le secret devenu inutile.

</Steps>

La suppression est refusée tant qu’une application actuelle, une tâche en cours ou une configuration de retour arrière disponible utilise encore le secret. Supprimez-le lorsque ces utilisations ont pris fin.
