## Créer et associer

Créez un secret texte ou fichier dans la page Secrets, puis sélectionnez-le dans la configuration de l’application. Le texte alimente une variable d’environnement ; le fichier est monté via XConfig.

## Permissions

Reader peut consulter les métadonnées. Operator et Admin peuvent créer, supprimer et associer les secrets. Le contenu ne peut être ni relu, ni téléchargé, ni modifié.

## Limites

Le contenu doit être non vide et ne pas dépasser 511 999 octets ; la description accepte 64 caractères. Le texte conserve les espaces et les sauts de ligne finaux, mais refuse NUL. Les fichiers acceptent les données binaires. Utilisez un fichier pour les contenus volumineux : les limites de l’environnement du processus peuvent être inférieures à celles du stockage.

## Remplacer et supprimer

Pour remplacer un secret, créez un nouveau nom, modifiez les références de chaque application et vérifiez le déploiement. Supprimez l’ancien uniquement quand les tâches et les configurations de retour arrière ne l’utilisent plus. Une référence contient le nom et l’ID ; recréer le même nom ne remplace pas les anciennes références.

## Exécution

Les fichiers sont montés en lecture seule avec le mode 0444. Les applications avec volumes locaux acceptent les secrets fichier, mais pas les téléversements XConfig ordinaires. XJob, XHealth, Hurl et Guardian héritent des associations ; les vérifications d’un candidat utilisent ses références. Une session exec ordinaire n’hérite pas automatiquement des variables injectées au démarrage.

## Visibilité

Les noms et descriptions sont des métadonnées visibles. Les applications et tâches peuvent écrire le contenu dans les journaux, sans masquage automatique. Conservez une copie source protégée. Les variables ordinaires et fichiers existants ne sont pas convertis automatiquement.
